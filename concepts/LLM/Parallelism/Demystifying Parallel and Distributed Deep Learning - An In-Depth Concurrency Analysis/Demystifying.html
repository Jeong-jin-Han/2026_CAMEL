Main topic 병렬 알고리즘 기초: DAG, Work-Depth, Allreduce 통신 하한
모든 계산은 DAG(정점=연산, 간선=데이터 의존성)로 모델링된다. 그래프의 총 work $\mathbf{W}$(정점 수)와 depth $\mathbf{D}$(최장 경로 길이)로 계산 복잡도를 특징짓고, p개 프로세서에서의 실행시간은 $\min\{\mathbf{W}/p, \mathbf{D}\} \le T_p \le O(\mathbf{W}/p + \mathbf{D})$로 유계다. 평균 병렬성은 $\mathbf{W}/\mathbf{D}$.

DNN의 텐서 연산은 대부분 데이터-병렬적이고, summation(allreduce 등 reduction 연산)만 의존성을 만든다. 분산 환경에서 allreduce는 노드 간 대역폭이 로컬 메모리 대역폭보다 훨씬 낮기 때문에 가장 비용이 큰 연산으로 꼽힌다 — 단순화된 LogP 모델(point-to-point latency L, per-byte cost G, P개 머신)에서 tree 알고리즘의 통신시간은 $T_{tree} = 2\log_2(P)(L+\gamma m G)$이고, 중복 계산을 허용하지 않으면 이론적 하한은 더 강해진다.
Original §2.5, p.9
In multi-machine environments, these tables are distributed across the machines which participate in the overall reduction operation. Due to the relatively low bandwidth between the machines (compared to local memory bandwidths), this operation is often most critical for distributed learning.
Main topic 효율성 트레이드오프: 미니배치 크기, 일반화 vs 활용률
SGD를 minibatch 단위로 실행하면 병렬성이 생기지만, minibatch 크기는 그 자체로 최적화 대상이다. 너무 작으면(region A) 하드웨어 병렬성을 못 살리고, 너무 크면(region C) 일반화 성능이 떨어진다 — 이 사이 어딘가(region B)가 실무적 최적점이다. 대규모 minibatch(8k, 32k, 심지어 64k)를 정확도 손실 없이 쓰려는 시도들은 학습률 워밍업, 배치-크기 기반 gradient variance 제어, 적응적 minibatch 증가 등으로 이 상한을 밀어올릴 뿐, 상한 자체를 없애지는 못한다.
Original §3, p.10
Overall, such works increase the upper bound on feasible minibatch sizes, but do not remove it.

Main topic 전체 네트워크 병렬성: Data / Model / Pipeline / Hybrid
Data parallelism은 미니배치를 프로세서에 나눠주고 gradient를 allreduce로 합친다 — 가장 널리 쓰이지만 Batch Normalization이 미니배치 전체에 걸친 동기화를 요구해 확장성 병목이 된다. Model parallelism은 뉴런·채널 차원으로 네트워크 자체를 쪼개 여러 프로세서에 배치 — 메모리는 아끼지만 레이어마다 통신이 필요하고, FC layer에서는 all-to-all 통신이 발생한다. Pipelining은 레이어 단위로 프로세서를 나눠 forward/backward/weight-update를 겹쳐 실행한다.

세 방식은 상호 배타적이지 않다 — DistBelief/Project Adam 같은 실제 시스템은 data parallelism(모델 복제본 간) + model parallelism(레이어 내 뉴런 분할) + pipelining(레이어 간)을 동시에 조합하는 hybrid parallelism을 쓴다.
Original §6.4, p.22
The combination of multiple parallelism schemes can overcome the drawbacks of each scheme. Below we overview successful instances of such hybrids.
Main topic 분산 학습: Model Consistency 스펙트럼과 중앙화 방식
분산 SGD에서 여러 training agent가 각자 파라미터 $w$의 사본을 들고 학습할 때, 모두가 항상 최신 $w$를 본다고 보장하면 'consistent'(synchronous), staleness를 허용하면 'inconsistent'(asynchronous, 대표적으로 HOGWILD)다. 스펙트럼 중간에 Stale-Synchronous Parallelism(SSP)이 있어 최대 staleness를 유계로 강제한다. 아키텍처 축으로는 parameter server(PS, 중앙집중) vs decentralized(allreduce 기반)로 나뉘며, PS는 fault tolerance·이질적 환경 대응에 유리하고 decentralized는 통신을 네트워크 전 경로에 분산시킬 수 있다.

실무에서는 32-50개 노드까지는 synchronous가 잘 확장되고, 그 이상 규모나 이질적 환경에서는 asynchronous/SSP가 선호된다는 관찰을 제시한다.
Original §7.1, p.24
In practical implementations, the prominently-used model consistency approaches are synchronous for up to 32–50 nodes, where the allreduce operation still scales nearly linearly; and asynchronous/SSP for larger clusters and heterogeneous environments
Main topic 통신량 줄이기: 압축과 Model Consolidation
통신 비용을 줄이는 두 축: (1) 메시지 개수를 줄이기(§7.1의 model consistency 완화), (2) 메시지 크기를 줄이기 — quantization(32비트를 더 적은 비트로, stochastic rounding으로 기댓값 보존)과 sparsification(작은 gradient는 아예 안 보냄, top-k 선택)이 대표적. Model consolidation은 아예 매 스텝 동기화를 포기하고, 학습 후(또는 아주 드물게) 여러 모델을 합치는 방식 — ensemble, knowledge distillation, model averaging(EASGD 등)이 있다.

Main topic 메타-최적화: 하이퍼파라미터 탐색과 Neural Architecture Search
학습 자체가 볼록하지 않은 최적화 문제이므로, 남는 계산 자원을 하이퍼파라미터 탐색(learning rate, momentum, staleness 등)이나 아키텍처 탐색에 쓸 수 있다. Architecture search는 세 갈래다: Sequential Model-Based Optimization(SMBO, 예: DARTS의 미분가능한 bi-level 최적화), Reinforcement Learning(정확도를 보상으로 삼아 레이어 구성을 액션으로), Evolutionary Algorithms(유전 인코딩+tournament selection). 모듈·블록의 self-similarity를 활용하면 탐색 공간을 계층적으로 줄일 수 있다.

Regularized Evolution(AmoebaNet)은 기존 수작업/RL 기반 탐색을 모두 능가하는 ImageNet 3.8% / CIFAR-10 2.13% 오차를 달성했다.

AmoebaNets outperform all existing methods, including manually engineered DNNs and RL-based searches, with 3.8% error for ImageNet and 2.13% error for CIFAR-10 (compared to 5.29% and 3.62% on the best instances of DenseNet, see Table 5).

저자들의 마무리 진단: 단일 오퍼레이터 최적화는 이미 고도로 성숙했고(§5), 현재 연구는 레이어-간·전체-DNN 최적화(TensorFlow XLA, TVM, Tensor Comprehensions 같은 컴파일러가 그래프 전체를 fusion 등으로 변환, 최대 4배 속도향상)로 옮겨가고 있다. 모바일·엣지 배포를 위한 post-training compression도 계속 중요해질 것. 분산 학습 기법들은 표준 프로그래밍 인터페이스로 수렴 중이며, 클라우드의 elastic 노드 스케줄링과 진화적 최적화가 결합해 '적응적이고 financially-viable한' 최적화로 이어질 것으로 전망한다.

Method DAG 실행시간의 이론적 상·하한

Method BN의 동기화 병목과 Weight Normalization의 우회
Batch Normalization은 미니배치 전체에 걸친 평균·분산을 계산해야 해서 완전한 동기화 지점이 된다 — data parallelism의 확장성을 해치는 대표 오퍼레이터. 실무에서는 최소 32개 샘플의 로컬 서브셋만으로 BN을 근사해 동기화를 로컬화한다. Weight Normalization은 가중치를 크기($g$)와 방향($v$)으로 재매개변수화해서 미니배치 간 의존성(depth) 자체를 $O(\log N)$에서 $O(1)$로 없앤다.
Original §6.1.1, p.19
WN decreases the depth (D) of the operator from O(log N) to O(1), removing inter-dependencies within the minibatch. According to the authors, WN reduces the need for BN, achieving comparable accuracy using a simplified version of BN (without variance correction).
Result Hybrid Parallelism 실측 스피드업 (AlexNet 등)
AlexNet을 4-GPU에서 data 또는 model parallelism 단독으로 매핑하면 최선이 약 2.2배. Convolution엔 data parallelism, FC엔 model parallelism을 섞으면 8-GPU에서 최대 6.25배(정확도 손실 <1%). 다른 hybrid 구현들도 4-GPU에서 3.1배를 재현했다. AMPNet은 fine-grained model parallelism을 비동기 스케줄링과 결합해 TensorFlow 대비 최대 3.94배.
Original §6.4, p.22

Claim PS든 decentralized든 결국 통신 대역폭·지연이 확장성을 결정
PS 방식이든 decentralized(allreduce) 방식이든, 어느 쪽을 쓸지는 네트워크 토폴로지·대역폭·통신 지연·업데이트 빈도·fault tolerance 요구에 달려있다고 저자들은 명시적으로 프레이밍한다. allreduce는 이론적으로 reduce-then-broadcast와 동일한 시간이 걸리고, PS는 통신을 특정 노드로 집중시키는 대신 fault tolerance와 이질성 대응력을 얻는다 — 이 절 전체가 '통신 자원을 어떻게 배분하느냐'의 트레이드오프로 요약된다.

Question HOGWILD/SSP의 수렴 증명, 비볼록 DNN에도 정말 유효한가?
HOGWILD류 비동기 SGD의 수렴 증명은 (a) atomic write, (b) Lipschitz 연속미분+강볼록성, (c) staleness 유계라는 세 조건에 의존한다(§7.1). 그런데 DNN의 손실함수는 일반적으로 비볼록(non-convex)이다. 저자들도 이 갭을 명시적으로 다루지 않고 '희소 학습 문제(sparse learning problems)'라는 조건부로 넘어간다 — 실제 대규모 비볼록 DNN 학습에서 이 수렴 보장들이 어느 정도까지 근사적으로 유효한지 궁금하다.
Original §7.1, p.23
Based on foundations of distributed asynchronous SGD, the proofs impose that (a) write-accesses (adding gradients) are always atomic; (b) Lipschitz continuous differentiability and strong convexity on fw; and (c) that the staleness, i.e., the maximal number of iterations between reading w and writing ∇w, is bounded.
