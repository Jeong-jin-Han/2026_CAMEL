Main topic KV Cache란? 그리고 메모리 문제의 등장 (§1-2)
LLM은 auto-regressive 디코딩 특성상 매 토큰 생성마다 이전 모든 토큰에 대한 attention을 다시 계산해야 해서 원래는 시퀀스 길이에 대해 quadratic한 시간복잡도를 갖는다. KV Cache는 이전 토큰들이 만든 Key/Value 텐서를 저장해두고 재사용해서 토큰당 생성 시간을 linear로 낮춘다.

하지만 공짜가 아니다: 시퀀스가 길어질수록 KV Cache 크기도 선형으로 커지고, 각 대화(dialogue)는 자신만의 KV Cache를 가져야 해서 서로 재사용하기 어렵다. 특히 GPU는 연산속도 대비 메모리 대역폭이 낮아(memory-bound) 이 문제가 더 치명적이다. 이 논문은 KV Cache 최적화 기법들을 LLM 생애주기(training → deployment → post-training) 순서로 정리한 리뷰다.
Original §1, p.1
KV Cache, by storing the keys and values tensor in attention module generated by past tokens, can reduce the time complexity required to generate each token to linear, greatly improving inference efficiency. However, the use of KV Cache is not all advantageous.
Main topic Training-Stage: 모델 아키텍처 자체를 바꿔 KV를 줄인다 (§3)
Pre-training 단계는 모델의 가소성(plasticity)이 가장 크기 때문에 KV Cache 압축이 가장 근본적으로 이뤄질 수 있는 지점이다. 이 챕터는 attention head 구조를 바꾸는 MQA/GQA, layer 간 KV를 공유·재사용하는 CLA/YOCO/GoldFinch, 그리고 저랭크 압축인 MLA까지, KV 헤드 수나 차원 자체를 줄이는 아키텍처 변경들을 다룬다. 단, 이 방법들은 기존에 학습된 모델에는 적용하기 어렵고 low-budget 세팅에는 안 맞는다는 한계가 있다.
Original §3, p.4
For LLMs that adopt the traditional Decoder-Only Transformer architecture, the most effective KV Cache compression method emerges during the pre-training phase. This is because, in this phase, the model possesses the greatest plasticity.
Main topic Deploy-Stage①: PagedAttention — 메모리 단편화 해결 (§4)
추론 시스템 관점에서 KV Cache는 두 가지 문제를 낳는다: (1) K/V를 계속 붙였다 뗐다 하면서 메모리가 반복적으로 할당·해제되어 단편화(fragmentation)가 심해진다, (2) KV Cache를 배치(batch) 처리하기 어려워 메모리 대역폭 병목이 심해진다.

PagedAttention(vLLM)은 OS의 페이지 메모리 기법을 그대로 GPU 메모리에 가져와, KV Cache를 연속된 공간이 아니라 불연속 블록(page)들로 나눠 저장하고 매핑 테이블로 관리한다. 그 결과 사실상 메모리 단편화 없이 효율적인 추론이 가능해졌고, 이후 등장하는 거의 모든 deploy-stage 시스템의 기반이 된다.
Original §4, p.5
From the perspective of inference systems, KV Cache presents significant challenges in two key areas. First, during the continuous {K, kn} −→ K and {V, vn} −→ V operations, memory is repeatedly allocated and released, resulting in substantial fragmentation. Second, the inability to batch-process KV Cache exacerbates severe memory bandwidth bottlenecks, leading to computational inefficiency.
Main topic Deploy-Stage②: 분산·계층형 KV 저장 시스템으로 확장 (§4)
PagedAttention이 단일 GPU 메모리 관리 문제를 풀었다면, 이 노드가 다루는 후속 연구들은 그 아이디어를 여러 서버·여러 저장매체로 확장한다. 순서대로: DistAttention/DistKV-LLM(단일 서버를 넘어 여러 서버에 분산 배치) → CachedAttention(GPU를 넘어 CPU/디스크까지 포함하는 계층적 다중 저장장치 시스템으로 대화 간 KV 재사용) → InfiniGen(중요 정보만 GPU에 남기고 나머지는 CPU로 offload한 뒤 speculative하게 필요한 부분만 다시 불러옴) → Mooncake(prefill/decoding을 분리하고 KV Cache를 중심에 둔 완전히 분리된(disaggregated) 아키텍처).

이 흐름 전체가 결국 'KV Cache를 어디에, 어떤 계층 구조로 둘 것인가'라는 메모리 시스템 설계 문제로 수렴한다는 점이 이 리뷰에서 가장 눈여겨볼 대목이다.
Original §4, p.5
Lin et al. (2024) further developed the idea of Paged Attention. Through the DistAttention it proposed and the DistKV-LLM built on it, KV Cache was able to achieve distributed deployment on multiple servers. This significantly improved the efficiency of providing LLM services using large-scale cloud servers.
Main topic Post-Training①: Eviction과 Merging — 토큰 자체를 줄이기 (§5.1)
학습이 끝난 모델을 건드리지 않고, 추론 중에 KV Cache에서 덜 중요한 토큰을 골라 버리거나(eviction) 합치는(merging) 방식이다. Eviction은 static policy(항상 초기 토큰+최근 토큰만 유지, attention sink/StreamingLLM)와 dynamic policy(매 스텝 attention weight 등으로 중요도를 추정, H2O/TOVA/PyramidInfer/Keyformer)로 나뉜다. Merging은 hardmax(버리기)에서 softmax(가중합치기)로 넘어간 확장으로, DMC/KVMerger/Anchor-LLM 등이 있다. 공통 난제는 '어느 영역을 합칠지'와 '어떤 방식으로 합칠지'다.
Original §5.1, p.6
Eviction methods are about the policies to discard unnecessary tokens. Two lines of approaches exist: static policies, which are designed before inference and remains consistent across every inference request, and dynamic policies, which utilize the information generated while inference to identify important tokens.
Main topic Post-Training②: Quantization — 정밀도를 낮추기 (§5.2)
KV Cache 값 자체를 저정밀도(low-bit)로 양자화하는 방법군이다. KV Cache-only quantization(모델 가중치는 그대로 두고 KV만 압축, 예: KVQuant/GEAR/QAQ/MiKV)과 full quantization(가중치까지 함께 압축, 예: FlexGen/WKVQuant)으로 나뉜다. Key는 채널별 outlier가 크고 Value는 토큰별 분포가 달라, per-channel/per-token처럼 K와 V에 서로 다른 양자화 전략을 쓰는 것이 핵심 트렌드다.
Original §5.2, p.7
Another commonly utilized method for compressing Key-Value (KV) cache is through quantization. This approach effectively compresses data by mapping tensor values, originally in full precision, to discrete levels and storing them at a reduced precision.
Main topic 평가: 데이터셋과 지표 (§6)
긴 문맥 능력을 평가하는 두 축: (1) LongBench/ZeroSCROLLS/L-Eval 같은 long-context bench(긴 문서를 읽고 질의응답), (2) Needle-in-a-Haystack/Passkey Retrieval/RULER 같은 key retrieval(관련 없는 텍스트 속에 숨긴 키를 찾기 — 더 단순하고 통제 가능하지만 지나치게 단순하다는 비판도 있음). 효율 지표로는 토큰당 GPU 메모리 사용량, throughput/latency가, 성능 지표로는 perplexity(PPL)가 쓰인다.
Original §6, p.9
In this section, we first introduce the datasets commonly used in KV Cache optimization, followed by a presentation of frequently used evaluation metrics.
Main topic Key Takeaways: 향후 방향 — 저장·검색 기술로 KV Cache를 넘긴다 (§7-8)
리뷰는 KV Cache 최적화의 핵심을 'K 또는 V를 어떻게 더 압축할 것인가'로 요약하고, 삭제(eviction)와 압축(compression) 중 무엇이 나은지는 아직 열린 질문이라고 정리한다. 가장 급진적인 방향으로 KV Cache를 GPU/CPU가 아닌 완전히 다른 저장매체(external storage medium)에 두고, 필요할 때 fetch해오는 retrieval 문제로 재정의하는 아이디어를 제시하며 리뷰를 마무리한다.
Original §7, p.10
These discussions point towards an evolving future where storage and retrieval technologies might become as crucial as the computational models themselves. Innovations in how KV Cache is managed, stored, and accessed could open up new avenues for making LLMs more efficient and versatile.
Method MQA (Shazeer 2019): head를 1개로 줄이기
Multi-Head Attention(MHA)에서 Key/Value head를 딱 1개만 남기고 Query head는 그대로 여러 개 유지하는 Multi-Query Attention(MQA). Value head가 하나뿐이라도 Query head 수만큼(n_h가지) 서로 다른 조합 가중치가 나오기 때문에 성능을 크게 해치지 않으면서 KV Cache를 1/n_h로 줄인다는 것이 핵심 주장이다. 다만 head를 1개로 줄이는 건 상당히 공격적인 전략이다.
Original §3, p.4
Shazeer (2019) proposed Multi-Query Attention (MQA) based on Multi-Head Attention (MHA). Shazeer claimed that even if we retain only one head for keys and values, we can still achieve satisfactory model performance.
Method GQA (Ainslie et al. 2023): head 수와 성능의 절충
MQA가 너무 공격적이라는 문제의식에서, Query head들을 n_g개 그룹으로 묶고 그룹마다 하나의 Key/Value head를 공유하는 Grouped Query Attention. n_g=1이면 MQA, n_g=n_h면 원래 MHA가 되는 일반화된 형태로, KV Cache 크기를 n_g/n_h 비율로 줄이면서 속도-성능 균형을 더 세밀하게 조절할 수 있다. Llama2/Qwen1.5 등 현재 오픈소스 LLM 다수가 GQA를 채택하고 있다(Appendix A, Table 2).
Original §3, p.4
Ainslie et al. (2023) proposed Grouped Query Attention (GQA), a method that can better balance speed and performance. In GQA, query heads are divided into n_g groups. Each group shares one key head, serving as the n_h/n_g different combination weights for the corresponding value head.
Method MLA (DeepSeek-AI 2024): 저랭크 압축으로 KV를 되살리기
layer 간 KV를 그대로 재사용하는 CLA/YOCO 방식을 '저랭크 압축(low-rank compression)의 한 형태'로 보고, 이를 더 밀어붙인 것이 Multi-Head Latent Attention(MLA)이다. KV를 저차원 latent로 압축해서 저장했다가, 추론 시 별도의 차원-확장 행렬(dimension-expanding matrix)을 곱해 원래 크기로 복원한다 — 단순 재사용이 아니라 실제로 압축·복원(decompression)을 한다는 점이 다르다. DeepSeek-V2가 이 방식을 채택했다.
Original §3, p.4-5
We can consider reuse as a form of low-rank compression, and complete low-rank compression should have even greater potential. The method proposed by DeepSeek-AI et al. (2024), called Multi-Head Latent Attention (MLA), exemplifies this. MLA achieves KV Cache decompression by utilizing an additional dimension-expanding matrix, rather than merely reusing the existing content.
Claim 주장: layer 재사용/저랭크 압축도 대역폭 병목은 못 고친다
CLA/YOCO/GoldFinch 같은 cross-layer KV 재사용이나 MLA 같은 저랭크 압축 모두, 메모리 용량(capacity)은 줄여주지만 메모리 대역폭 병목(memory bandwidth bottleneck) 자체는 해결하지 못한다는 것이 저자들의 핵심 비판이다. 특히 layer 간 재사용은 캐시 접근 패턴을 오히려 흩어지게(scattered) 만들어서, 정교하게 짠 CUDA 커널 없이는 서로 다른 캐시 레벨 간 데이터 이동량을 줄이는 게 애초에 불가능할 수도 있다고 지적한다.
Original §3, p.4
However, it's essential to note that these methods do not optimize the memory bandwidth bottleneck of the KV Cache. Cross-layer reuse results in scattered access to the same KV Cache, and only meticulously crafted CUDA kernels can effectively reduce data exchanges between different cache levels, if such reduction is possible at all.
Method PagedAttention / vLLM (Kwon et al. 2023)
OS의 가상메모리 페이징(paging) 기법을 GPU KV Cache 관리에 그대로 대응시킨 것. KV Cache를 연속된 하나의 큰 버퍼가 아니라 고정 크기 block들로 쪼개 불연속적으로 저장하고, block들을 논리적 시퀀스에 매핑하는 테이블을 따로 둔다. 이 덕분에 시퀀스 길이가 늘어나거나 줄어들 때마다 생기던 내부/외부 단편화가 거의 사라지고, block 단위 CUDA 커널로 효율적인 attention 계산이 가능해졌다.
Original §4, p.5
Kwon et al. (2023) introduced the Paged Attention mechanism and the vLLM framework. Paged Attention draws on the page memory mechanism widely used in CPU memory, and uses an additional mapping table to map the KV Cache that used to be stored continuously to discontinuous GPU memory.
Method DistAttention / DistKV-LLM (Lin et al. 2024)
PagedAttention의 페이징 개념을 단일 GPU/서버를 넘어 여러 서버로 확장한 것. DistAttention이 attention 계산 자체를 여러 서버에 분산하고, 그 위에 구축된 DistKV-LLM이 KV Cache를 여러 서버에 걸쳐 분산 저장·관리한다. 대규모 클라우드 서버 환경에서 LLM 서빙 효율을 크게 끌어올렸다고 보고한다.
Original §4, p.5
Lin et al. (2024) further developed the idea of Paged Attention. Through the DistAttention it proposed and the DistKV-LLM built on it, KV Cache was able to achieve distributed deployment on multiple servers. This significantly improved the efficiency of providing LLM services using large-scale cloud servers.
Method CachedAttention (Gao et al. 2024): 계층적 다중 저장장치
ChunkAttention(Ye et al. 2024)이 대화들 사이에서 공통 접두사(longest common prefix)를 트리로 찾아 KV Cache를 재사용해 prefill 단계를 가속했다면, CachedAttention은 여기서 한 걸음 더 나아가 GPU 메모리 하나가 아니라 여러 저장장치(예: GPU 메모리 → CPU 메모리 → 디스크)를 계층적으로 엮은 시스템을 도입한다. 즉 multi-turn 대화의 KV Cache를 저장 계층 전체에 걸쳐 관리한다는 것이 핵심.
Original §4, p.5
Moreover, Gao et al. (2024) extend this idea by introducing a hierarchical system that utilizes multiple storage devices.
Method InfiniGen (Lee et al. 2024): CPU offload + speculative reload
KV Cache의 대부분을 CPU로 offload해두고, GPU에는 핵심적인 일부(critical components)만 남겨둔다. 추론 중에는 남겨둔 최소한의 정보를 근거로 어떤 KV가 다음 스텝에 필요할지 speculative하게 예측해서, 그 부분만 CPU에서 GPU로 다시 불러온다. 결과적으로 대규모 데이터 교환 없이도 고속 연산장치(GPU)의 메모리를 아낄 수 있다고 주장한다.
Original §4, p.5
Jin et al. (2024) and Lee et al. (2024) offload KV Cache to CPU with speculation. The core idea is to offload the primary portion of the KV Cache to the CPU, retaining only critical components. During inference, by speculatively reloading a small amount of KV cache onto the GPU using the limited preserved information, we can save memory space on high-speed computational devices without compromising performance, all while avoiding extensive data exchanges.
Method Mooncake (Qin et al. 2024): KV-cache-centric disaggregated architecture
실제 프로덕션 서빙 시스템을 다룬 엔터프라이즈 관점의 기술 보고서. prefill과 decoding을 서로 다른 자원 풀로 분리(disaggregate)하고, 그 중심에 KV Cache를 두어 전체 추론 시스템 차원에서 최적화한다 — 지금까지의 deploy-stage 기법들(paging, 분산, 계층적 저장, offload)이 실제 대규모 서비스에서 어떻게 합쳐지는지 보여주는 사례로 인용된다.
Original §4, p.5
Additionally, Qin et al. (2024) provides a comprehensive technical report from an enterprise perspective, optimizing the entire inference system.
Method Static eviction: attention sink / StreamingLLM
가장 단순한 고정 크기 전략은 최근 토큰만 남기는 sliding window attention이지만, 시퀀스가 캐시 크기를 넘으면 성능이 붕괴한다. Xiao et al.(2023)과 Han et al.(2024)은 layer/head에 상관없이 '초기 토큰들'이 거의 항상 높은 attention weight를 받는다는 attention sink 현상을 발견했고, 그래서 초기 토큰 + 최근 토큰만 유지하면 성능이 유지된다는 것을 보였다(StreamingLLM).
Original §5.1, p.6
A straightforward approach for maintaining a fixed-size KV Cache is to retain recent tokens, known as slide window attention (Beltagy et al., 2020). However, the model will collapse when sequence length exceeds cache size (Xiao et al., 2023). Recently, Xiao et al. (2023) and Han et al. (2024) proposed that initial tokens almost consistently receive high attention weights across layers and heads.
Method Dynamic eviction: H2O / TOVA / PyramidInfer / Keyformer
attention weight 히스토리로 토큰의 미래 중요도를 추정하는 계열. H2O는 누적 정규화 attention score로 유지할 토큰을 정하면서 최근 토큰도 함께 보존한다. TOVA는 매 스텝 attention weight가 가장 작은 토큰을 그리디하게 버린다. PyramidInfer는 깊은 layer일수록 문맥 중복(redundancy)이 크다고 보고 layer별로 캐시 길이를 점점 줄여 '피라미드' 모양을 만든다. Keyformer는 토큰을 너무 많이 버리면 남은 토큰들의 attention 분포가 왜곡된다는 점을 보완하는 기법이다.
Original §5.1, p.6
H2 Eviction Algorithm (Zhang et al., 2023) uses accumulative normalized attention scores to decide which token to stay and at the same time keeps the recent tokens since they may show strong correlations with current tokens.
Method Merging: DMC / KVMerger / Anchor-LLM — hardmax에서 softmax로
토큰을 통째로 버리는 대신 여러 토큰의 K/V를 하나로 합치는(merging) 접근. Eviction의 hardmax(버림/유지 이분법)를 softmax(가중치를 둔 병합)로 확장한 것으로 볼 수 있다. DMC는 파인튜닝으로 병합 여부를 판단하는 차원 하나를 학습하고, KVMerger는 가우시안 가중치+attention score로 병합하며, Anchor-LLM은 학습 단계에서부터 앵커 토큰으로 KV를 병합하도록 가르친다. 공통 난제는 '어느 영역을 병합할지'와 '어떤 방식으로 합칠지' 결정하는 것이다.
Original §5.1, p.7
Merging, as a relatively recent method, represents a natural extension of Eviction, transitioning from hardmax to softmax. The current key challenges in this area include determining the merging region and selecting an appropriate scheme for combining keys and values.
Method KVQuant (Hooper et al. 2024): Key/Value에 다른 양자화 전략
Key 행렬은 다른 채널들보다 평균 크기가 훨씬 큰 outlier 채널을 갖는다는 관찰에서 출발해, Key는 채널 단위(per-channel), Value는 토큰 단위(per-token)로 서로 다른 양자화 전략을 쓴다. 여기에 RoPE로 인한 왜곡을 줄이는 처리, outlier를 분리해 양자화 구간의 왜곡을 줄이는 기법, 2-bit급 초저정밀도에서 특히 도움이 되는 양자화 중심값 정규화까지 더해 KVQuant를 구성한다.
Original §5.2, p.7-8
Hooper et al. (2024) further identified that Key matrices in language models often exhibit distinct outlier channels characterized by larger average magnitudes compared to others. To address this, They proposed KVQuant, a method to quantize Key and Value activations using distinct strategies.

Question 열린 질문: Eviction(삭제) vs Compression(압축), 뭐가 나은가?
리뷰가 스스로 던지는 질문이다. 덜 중요한 KV를 아예 지우는 eviction은 즉각적인 메모리 절감 효과가 크지만 성능 손실 위험이 있고, 지우지 않고 압축(quantization/merging 등)하는 쪽은 정보를 최대한 보존하려 하지만 압축 자체의 오버헤드나 한계가 있다. 이 논문은 두 접근 중 어느 쪽이 근본적으로 더 나은 전략인지에 대한 답을 내리지 않고 열어둔다.
Original §7, p.10
Whether to delete less important KV pairs to save memory or to compress the KV Cache without deletion remains an open question. While deletion might offer immediate memory relief, it could potentially compromise the model's performance. In contrast, better compression techniques strive to retain information integrity while reducing memory footprint.
Gap / Idea Gap: '외부 저장매체 KV Cache'를 제안만 하고 메커니즘은 안 정한다 — CXL이 그 후보
논문은 §7에서 KV Cache를 GPU/CPU가 아닌 '다른 저장매체(different storage medium)'에 두고 필요할 때 fetch하는 retrieval 문제로 재정의하자는 방향만 제시하고, 그 저장매체가 무엇이고 어떤 인터커넥트·일관성 모델로 GPU와 묶일지는 전혀 specify하지 않는다. 이미 Mooncake(node_017)가 KV-cache-centric disaggregated architecture를 실제 프로덕션에서 구현했지만, 이는 네트워크(RDMA 등)로 묶인 여러 서버 간 소프트웨어 수준 분리다.

내 관심사인 CXL 기반 memory disaggregation/pooling은 바로 이 '외부 저장매체'를 GPU/CPU와 같은 memory 주소공간에 캐시-coherent하게 노출시키는 하드웨어 메커니즘 후보다. 즉 저자들이 상상한 'KV Cache as a retrieval problem'을 CXL.mem/CXL.cache 계층에서 어떻게 구현할지가, 이 논문이 명시하지 않은 채 남겨둔 설계공간이다.
Original §7, p.10
A more radical approach could involve storing the KV Cache externally, possibly on a different storage medium. This method would transform KV Cache management into a retrieval challenge, where the relevant KV pairs are fetched and reintegrated into the model as needed. While this could reduce memory usage on primary devices, it would introduce complexities in retrieval and integration processes.
Memo 내 연구방향과의 연결: 계층적 다중 저장장치 관리가 이미 여기 있다
CachedAttention의 '여러 저장장치를 계층적으로 엮는다'는 아이디어와 Mooncake의 'KV-cache-centric disaggregated architecture'는 사실상 내가 보는 tiered memory / memory disaggregation 문제를 애플리케이션 레이어(스케줄러+캐시 정책)에서 이미 풀고 있는 사례다. 차이는 이들이 기존 네트워크 스택(RDMA, TCP) 위에서 소프트웨어적으로 계층을 관리한다는 점 — 만약 이 계층 관리를 CXL 같은 메모리-시맨틱 인터커넥트로 하드웨어에 내려보내면(coherence를 HW가 보장), 지금 이 논문들이 소프트웨어로 힘들게 하고 있는 prefetch/eviction/consistency 관리 중 어디까지가 불필요해지는지가 궁금하다.

Memo Appendix A, R 지표: GQA는 토큰당 실제 메모리 용량을 얼마나 줄이나
Appendix A의 R = (토큰당 KV Cache 크기) / (임베딩 벡터 크기) 지표는 결국 GPU 메모리 capacity planning에 바로 쓸 수 있는 숫자다. GQA를 쓰는 모델들은 이 R 값이 non-GQA 대비 훨씬 낮다(Table 2) — 예: LLaMA2-69B(GQA)는 R=20인데 LLaMA2-13B/6.7B(non-GQA)는 R=80/64다. 아키텍처 설계 선택 하나가 실제 서빙에 필요한 물리 메모리 용량을 몇 배씩 바꾼다는 걸 보여주는 수치라, HW 메모리 시스템을 설계할 때 '어떤 attention 아키텍처를 가정할 것인가'가 얼마나 중요한 입력값인지 다시 확인시켜준다.
Original Appendix A, p.17
R: Represents the ratio of the KV Cache size generated for each token to the size of the embedding vector. A higher ratio indicates that the information for this token has been expanded by a greater factor. Notably, when using the GQA method, this value is significantly lower compared to non-GQA methods, implying that the information produced is relatively compressed.
