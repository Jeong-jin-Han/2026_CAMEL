Main topic 추론 비용의 세 축: Latency, Throughput, MFU 트레이드오프
생성형 Transformer 추론의 비용을 재는 세 지표: latency(전체 추론 시간, prefill+decode로 분해), throughput(초당 처리/생성 토큰 수), MFU(model FLOPS utilization, 관측 처리량 대비 이론적 최대 처리량 비율). 저자들은 이 셋 사이의 근본적 트레이드오프를 분석한다.

메모리 비용 관점에서 핵심 관찰: 배치 크기와 시퀀스 길이가 작을 때는 weight를 HBM에서 로드하는 시간이 지배적이고(weight-loading이 병목), 배치·시퀀스 길이가 커지면(예: 2048+ 토큰에 배치 512+) KV cache를 로드하는 시간이 지배적으로 바뀐다. 이 KV cache 로딩 동안 칩의 연산 코어는 사실상 idle 상태다 — 즉 decode 단계는 본질적으로 memory-bandwidth-bound다.
Original §2, p.3
At small batch sizes and sequence lengths, the time to load weights dominates. At larger batch sizes and sequence lengths (e.g. 2048+ tokens with batch size 512+), the time to load the KV cache dominates.

Main topic 파티셔닝 표기법과 통신 collective (BLE, all-gather/reduce-scatter/all-to-all)
저자들은 텐서 shape를 B(batch)·L(sequence)·E(model/embed dim)·F(feedforward dim)·H(heads)로 표기하고, 아래첨자로 TPU v4 3D torus의 X/Y/Z 축 중 어디에 분할됐는지 표시한다(예: BLE_xyz는 E를 X×Y×Z개 조각으로 분할). 축이 표기에서 생략되면 그 축은 복제(replicated)된 것이고, 'partialsum-x'는 x축에 대해 아직 합산 전인 부분합임을 뜻한다.

세 가지 핵심 통신 collective: all-gather(x)는 x축을 따라 텐서를 모아 x배 큰 복제 텐서로 만들고, reduce-scatter(x)는 x축에 대해 부분합을 리듀스하면서 동시에 샤딩하며, all-reduce(x)는 이 둘을 합친 것(리듀스+브로드캐스트)이다. all-to-all은 한 텐서 차원의 샤딩을 다른 차원으로 옮긴다(예: BLH_xQ → B_xLHQ).
Original §3.1, p.4
We use several communication collectives originating from MPI (Clarke et al., 1994). The all-reduce(x) primitive sums a partialsum tensor such as BLEyz(partialsum-x) across sets of chips in the x axis of the torus and broadcasts the sum back to all the involved chips, returning BLEyz.
Main topic Feedforward 파티셔닝: 1D/2D Weight-Stationary vs Weight-Gathered
FFN 가중치를 칩에 분산하는 세 가지 레이아웃. (1) 1D weight-stationary: E×F 가중치를 d_model 또는 d_ff 한 축으로만 나눠 각 칩에 고정하고, activation을 all-gather/reduce-scatter로 주고받는다. 통신시간이 칩 수에 무관하게 거의 일정해서 칩이 늘수록 병목이 된다. (2) 2D weight-stationary: 가중치를 E와 F 두 축 모두로 나눠(E_x F_yz) 통신량을 O(1/√n_chips)로 줄인다 — √n_chips > d_ff/d_model(보통 n_chips>16)일 때 1D보다 효율적. (3) weight-gathered: activation을 고정하고 가중치를 칩 간에 통째로 옮기는 방식으로, 배치가 매우 클 때(활성값이 가중치보다 커질 때) 더 경제적이다.
Original §3.2.2, p.5
2D weight-stationary becomes more communication-efficient when √nchips > dff/dmodel. Since typically dff = 4dmodel, this occurs when nchips > 16.
FFN 파티셔닝 전략별 통신 비용 공식
| 전략 | 통신 시간 |
|---|---|
| 1D weight-stationary | $\frac{2BLE}{\text{bw}}$ |
| 2D weight-stationary | $\frac{8BLE}{\sqrt{n_{chips}}\,\text{bw}}$ |
| Weight-gathered (XYZ) | $\frac{4E\sqrt{BLF}}{\sqrt{n_{chips}}\,\text{bw}}$ |

weight-stationary 계열은 배치토큰수(BL)에 선형, weight-gathered 계열은 √BL에 비례 — 배치가 커질수록 weight-gathered가 유리해진다.
Main topic Multiquery Attention: 배치 축으로 샤딩해 KV cache 메모리비용 절감
Multihead attention은 head마다 별도 K/V를 갖지만, multiquery attention(Shazeer 2019; PaLM도 채용)은 Q는 그대로 n_heads개를 두되 K/V는 단 하나의 head만 두고 모든 query head가 공유한다. 이것만으로 KV cache 크기가 n_heads배 줄어든다.

그런데 기존 방식대로 head 축으로 샤딩하면(Fig.4b), K/V head가 하나뿐이라 각 칩에 그대로 복제해야 해서 multiquery의 메모리 절감 효과가 사라진다. 저자들이 제안하는 대안은 Q/K/V를 batch(B) 축으로 n_chips개로 쪼개는 것(Fig.4c) — 이러면 각 칩은 자기 몫의 시퀀스에 대한 K만 있으면 되므로 칩당 KV cache 메모리비용이 n_chips배 줄어든다. 대가는 activation을 재정렬하기 위한 all-to-all 통신이 추가된다는 것.
Original §3.3, p.6
An alternative approach, called multiquery attention (Shazeer, 2019; Chowdhery et al., 2022), still emits nheads for the query tensor, but only a single head for the key and value tensors. This key and value head is shared across the nheads query heads. This reduces the size of the KV cache tensors by a factor of nheads and hence the memory time spent loading them.
Main topic Parallel formulation + Looped CollectiveEinsum + int8 양자화
세 가지 저수준 최적화. (1) Parallel attention/FFN: layernorm된 입력에서 attention과 FFN을 각각 독립으로 계산해 더한다(직렬 대신 병렬). layernorm이 레이어당 1번으로 줄고, FFN의 입력 행렬을 attention의 W_Q와, W_K/W_V를 서로, W_O와 FFN 출력행렬을 각각 fuse할 수 있어 더 큰 GEMM으로 뭉쳐진다. 무엇보다 d_ff/n_heads 파티셔닝에 필요한 all-reduce 2번 중 1번이 아예 없어져서 통신시간이 절반으로 준다.

(2) Looped CollectiveEinsum: 통신(reduce-scatter/all-gather)을 계산과 동시에 진행되도록 겹치는 기법(Wang et al. 2023). reduce-scatter를 batch/sequence 축이 아니라 hidden 축(E 또는 F)으로 하도록 선택해 이 겹침 기회를 늘렸다.

(3) AQT 라이브러리로 16비트 가중치를 int8로 양자화 — 품질 저하 없이 weight-loading 메모리시간과 weight-gathered 레이아웃의 통신량을 줄인다.
Original §3.4, p.7
The benefits from the parallel formulation are as follows. First, there is only one layernorm per layer instead of two, which reduces latency at small batch sizes.
Main topic PaLM 540B 사례 연구: 저지연 29ms/token, 고처리량 76% MFU
PaLM 계열(8B/62B/540B, bfloat16 또는 int8)에 걸쳐 효율-지연 파레토 프론티어를 구했다. 540B, 64 TPU v4 칩 기준: 저배치(생성) 구간에서 int8 가중치로 28.5ms/token(bfloat16은 36.9ms/token), 대배치(prefill) 구간에서 76% MFU를 달성 — 이는 2048 토큰 컨텍스트를 지원하면서 나온 수치다. 비용은 chip-seconds per token = n_chips × time / (B×L)로 정의되며, MFU에 반비례한다. 배치512 근처가 최소 비용 지점이고, 배치를 줄이면 지연은 개선되지만 토큰당 비용은 늘어난다(최소 지연은 배치512 대비 3배 낮다).

Main topic 결론: FLOP·통신량이 근본 한계, sparsity/MoE가 향후 방향
이 논문은 500B+ 파라미터 모델을 64+ 칩으로 확장하는 실전 파티셔닝 원칙을 제시했다고 요약한다. 다만 저자들 스스로 인정하듯, dense Transformer의 FLOP 수와 통신량 자체가 성능의 근본 한계다. task-based mixture-of-experts 같은 sparsity 기법이나, 입력·생성 스텝마다 계산량을 다르게 배정하는 adaptive computation 기법이 토큰당 FLOP을 줄여줄 잠재력이 있다고 언급하며 향후 연구로 남긴다.
Original §7, p.11
we observe that FLOP count and communication volume can fundamentally limit performance of dense Transformer models. Sparsity techniques, such as task-based mixture of expert architectures... and adaptive computation techniques that allocate different amounts of compute per input and generation timestep... promise to reduce FLOPs per token of Transformer models.

int8 weight의 PaLM 540B를 64 TPU v4 칩에 올렸을 때: 사용자 입력 64토큰을 처리하고, 캐시된 대화 이력 1920토큰을 참조하고, 64토큰 응답을 생성하는 전체 과정이 1.9초에 끝난다. 오프라인 throughput 시나리오에서는 입력 1984토큰+출력 64토큰 처리에서 전체 FLOPS 효율 73%를 달성한다.
Original §1, p.2
For an interactive application such as a chatbot running on PaLM 540B with int8 weights, our implementation on 64 TPU v4 chips can process 64 tokens of text from a user, consult a cached conversation history of 1920 tokens, and generate a 64-token response in a total of 1.9 seconds.
Result KV cache가 파라미터보다 3배 커지는 지점
배치 512, 컨텍스트 길이 2048에서 KV cache 총량은 3TB로, 모델 파라미터 크기의 3배에 달한다. 이 KV cache를 생성되는 토큰마다 매번 off-chip 메모리에서 새로 로드해야 하고, 그동안 칩의 연산 코어는 사실상 놀고 있다 — decode 단계에서 메모리 대역폭이 병목이 되는 물리적 근거다.
Original §2, p.3
cache grows large: for batch size 512 and context length 2048, the KV cache totals 3TB, which is 3 times the size of the model's parameters. The on-chip memory needs to load this KV cache from off-chip memory once for every token generated during which the computational core of the chip is essentially idle.
Method Appendix A.1: all-gather/reduce-scatter 통신시간 공식
K개 파티션에 대한 all-gather에서, 각 칩이 크기 D의 출력을 만든다면 통신 패턴은 (K-1)/K 비율의 데이터를 (K-1)개 링크에 걸쳐 전송해야 한다. 따라서 $T_{comm(all-gather)} = \frac{D}{bw} \times \frac{K-1}{K}$. reduce-scatter도 같은 공식이되 D가 더 큰 입력 버퍼 크기가 된다. all-reduce는 이 둘을 합친 것이므로 $T_{comm(all-reduce)} = 2 \times T_{comm(all-gather)}$. K≫1로 가정하면 (K-1)/K ≈ 1로 근사해서 계산을 단순화한다.
Original Appendix A.1, p.15
For an all-gather over K partitions, where each chip produces an output of size D, the communication pattern requires chunks of size D/K to be transferred over (K − 1) interconnect links in the process of getting copied to (K − 1) chips.
Method 1D weight-stationary 통신시간 공식
각 칩은 reduce-scatter/all-gather에서 각각 BLE shape(비분할)의 입출력을 주고받는다. 유도 결과 $T_{comm} = \frac{2BLE}{\text{network bandwidth}}$ — 칩 수(n_chips)가 분모에 없다는 게 핵심: 칩을 늘려도 통신시간이 줄지 않아 결국 병목이 된다.
Original §3.2.1, p.4
In this 1D weight-stationary partitioning strategy, each chip gets inputs and outputs of shape BLE in the reduce-scatter and all-gather respectively.
Method 2D weight-stationary: X=0.5√n, YZ=2√n 최적 분할
가중치를 E_x F_yz로 분할, X×Y×Z=n_chips 제약에서 통신시간을 최소화하는 값은 X=0.5√n_chips, YZ=2√n_chips(d_ff=4d_model 가정). 결과 통신시간 $T_{comm} = \frac{8BLE}{\sqrt{n_{chips}}}$ — 분모에 √n_chips가 있어 칩을 늘릴수록 통신시간이 계속 줄어든다(1D와 대비되는 핵심 장점).
Original §3.2.2, p.5
We have a free choice of X, Y and Z subject to available TPU v4 slice shapes and X × Y × Z = nchips. Assuming dff = 4 × dmodel, we achieve the minimum communication time with X = 0.5 × √nchips and Y Z = 2 × √nchips.
Result Weight-gathered는 배치가 커지면 √BL로만 증가 (Fig.3)
weight-stationary 계열의 통신시간은 배치 토큰수(BL)에 선형으로 비례하지만, weight-gathered 계열은 √BL에만 비례한다. 그래서 배치와 prefill 시퀀스 길이가 충분히 커지면 weight-gathered가 더 싸진다 — Figure 3은 토큰수가 커질수록 최적 레이아웃이 2D weight-stationary에서 X→XY→XYZ weight-gathered로 순차적으로 전환됨을 보여준다.
Original §3.2.3, p.6
The communication time for the weight-stationary layout is linear in BL, while the communication time for the weight-gathered layout is linear in √BL. Therefore, the weight-gathered layout becomes cheaper when the batch size and prefill sequence length are sufficiently large.

Claim 핵심 주장: batch 샤딩이 칩당 KV cache 메모리비용을 n_chips배 줄인다
Q/K/V를 batch 축으로 n_chips개 파티션에 나누는 제안 레이아웃(Fig.4c)에서, 각 칩은 자기 몫 시퀀스의 K/V만 로드하면 되므로 칩당 KV cache 로딩에 드는 memory time이 정확히 n_chips분의 1로 줄어든다는 것이 이 논문의 핵심 주장이다. 이는 head 축 샤딩(Fig.4b, K/V head를 각 칩에 복제해야 함)과 근본적으로 다른 절감 메커니즘이다.
Original §3.3, p.6-7
We instead propose a partitioning strategy for the multiquery attention where the Q, K, and V matrices are partitioned over the batch B dimension into nchips partitions. Figure 4(c) shows that this reduces the memory cost of loading the KV cache per chip by a factor of nchips, thereby reducing the memory time by the same factor.

Result AQT int8: 품질저하 없이 weight 메모리비용 절감
AQT(Accurate Quantized Training) 라이브러리로 16비트 가중치를 int8로 변환해 눈에 띄는 품질 저하 없이 메모리비용을 줄인다. 이는 특히 저배치 구간(weight-loading이 지배적인 구간)에서 도움이 크고, weight-gathered 레이아웃의 통신량도 줄인다. activation quantization은 이 논문에서는 구현하지 않았지만, 향후 compute time과 통신량을 추가로 줄일 수 있을 것으로 기대한다고 언급.
Original §3.6, p.7-8
We use the AQT library (Lew et al., 2022) to reduce the memory cost of 16-bit weights by converting them to int8 without noticeable quality loss.
Claim 실증: parallel formulation이 직렬 대비 decode 지연 14% 감소
2D weight-stationary, 64칩, 배치512 조건에서 직렬(serial) attention/FFN 구성은 병렬(parallel) 구성 대비 스텝당 inference latency가 14% 더 높다 — activation 통신시간이 늘기 때문이다. prefill 단계에서는 weight-gathered 레이아웃이 activation 통신을 덜 필요로 하므로 이 차이가 줄어든다.
Original §4.3, p.9
The serial formulation incurs 14% higher inference latency per step than the parallel version because of the increased communication time for activations.
Result 실제 최소 latency: int8에서 28.5ms/token (bf16 대비 약 2배 비용 개선)
Figure 1(left)의 파레토 프론티어에서 얻어지는 구체적 수치: PaLM 540B, 배치64에서 int8 가중치로 28.5ms/token, bfloat16 가중치로는 36.9ms/token. 저지연 목표에서는 비용이 weight-loading 시간에 지배되므로 양자화가 비용을 약 2배 개선하지만, 대배치(비용이 compute-time에 지배)에서는 int8과 bfloat16의 비용 차이가 훨씬 작아진다(matmul 자체는 여전히 bfloat16 연산).
Original §4.4, p.9
We observe that int8 weight quantization achieves the minimum latency in Figure 1 (left): for example, we achieve 28.5ms/token with int8 weights at batch size 64 on PaLM 540B, while we achieve 36.9ms/token with bfloat16 weights.
Result FasterTransformer의 32-way TP는 33% MFU에서 정체 — 통신 병목
FasterTransformer는 8/16/32-way tensor parallelism 결과를 보고하는데, 32-way에서 최대 33% MFU에 그친다(16-way의 46% MFU보다 오히려 낮음 — TP를 더 늘리면 통신 병목으로 역효과). 반면 이 논문의 2D weight-stationary 파티셔닝은 64-way tensor parallelism까지 확장해도 44% MFU를 유지한다 — TPU v4의 더 빠른 인터커넥트 도메인과 √n_chips 스케일링 통신 공식 덕분이라고 해석.
Original §5, p.11
In contrast, our implementation is able to scale up to 64-way tensor parallelism while still achieving 44% MFU, suggesting superior scalability of our 2D weight-stationary partitioning strategy on TPU v4's larger high-speed interconnect domains.
Gap / Idea KV cache가 CXL 같은 느리지만 큰 메모리 티어로 spill한다면?
이 논문의 메모리-절감 논증(multiquery로 KV cache를 n_heads배, batch 샤딩으로 다시 n_chips배 줄이는 것)은 철저히 '어느 칩의 HBM에 몇 바이트가 있는가'를 조정하는 compute-side 샤딩 문제다 — 메모리 계층(tiering) 자체는 건드리지 않는다.

만약 KV cache 일부를 CXL 같은 disaggregated, 용량은 크지만 대역폭/지연이 HBM보다 못한 티어로 흘려보낼 수 있다면 어떻게 될까? 두 가능성이 있다: (1) 직교(orthogonal) 가설 — 이 논문의 통신 비용 모델(network bandwidth 한 항으로 뭉뚱그려진 T_comm 공식들)에 CXL 티어의 별도 대역폭/지연 항만 추가하면 되고, 샤딩 전략 자체는 그대로 재사용 가능하다. (2) 비직교 가설 — capacity가 사실상 무제한(pooled CXL)이 되면 애초에 '칩당 KV cache 메모리비용을 n_chips배로 나누는' 동기 자체가 약해진다(Table 1의 컨텍스트 길이 제약이 사라지므로), 대신 문제가 대역폭/latency 쪽으로 완전히 옮겨간다. 이 논문은 이 축을 전혀 다루지 않는다.
Question 이 통신비용 모델은 TPU v4 3D torus를 벗어나도 성립하는가?
Appendix A.1의 all-gather/reduce-scatter 비용 공식은 논문이 '대부분의 실제 네트워크 토폴로지에 대해 성립하는 일반적 모델'이라고 주장하지만, 최적 X/Y/Z 분할(예: 2D weight-stationary의 X=0.5√n, YZ=2√n)은 명시적으로 TPU v4의 3D torus 축 구조를 전제로 유도됐다. NVLink 스위치 패브릭(모든 GPU 쌍이 균일 대역폭)이나 CXL 스위치 토폴로지처럼 '축'이라는 개념 자체가 없는 인터커넥트에서는 이 X/Y/Z 인수분해가 어떻게 재정의돼야 하는지 논문은 다루지 않는다.

Memo 내 연구방향과의 연결: 이 논문의 병목은 '메모리 대역폭', 내 질문은 '메모리 계층'
이 논문 전체의 출발점은 decode 단계가 본질적으로 memory-bandwidth-bound라는 것(§2, KV cache가 파라미터의 3배까지 커짐)이고, 해법은 그 바이트들을 더 많은 칩의 HBM에 나눠 담아 칩당 대역폭 요구량을 낮추는 것(compute-side sharding)이다. 내가 보고 있는 CXL/disaggregation 방향은 반대편에서 같은 병목을 공격한다 — 칩 수를 늘리는 대신 메모리 자체를 계층화(capacity tier ↔ bandwidth tier)해서 문제를 푼다.

흥미로운 지점은 이 두 접근이 서로 배타적이지 않다는 것 — 이 논문의 샤딩 전략은 '한 노드 안에 몇 개의 동질적 HBM 칩이 있는가'를 전제로 하는데, 만약 그 노드 자체가 이미 CXL로 확장된 이종(heterogeneous) 메모리 풀을 갖고 있다면, 샤딩 축(X,Y,Z)에 '메모리 티어'라는 새 차원을 추가해야 할 수도 있다. 이건 이 논문이 전혀 다루지 않는, 내 박사 연구가 채울 수 있는 빈틈으로 보인다.
