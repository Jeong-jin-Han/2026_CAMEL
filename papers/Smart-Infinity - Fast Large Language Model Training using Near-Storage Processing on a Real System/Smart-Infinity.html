Main topic 문제 — GPU 메모리 한계와 storage-offloaded training의 대역폭 병목 ▼
LLM은 파라미터 수 증가로 GPU 메모리 용량이 최대 제약이 되어, 연산이 아니라 용량 때문에 수십 개 GPU를 쓰는 낭비가 생긴다. 대안인 storage-offloaded training은 optimizer states·gradients를 host memory와 SSD로 내보내 GPU 용량 벽을 넘지만, SSD 대역폭이 GPU 메모리보다 수 배수 낮아 새 병목이 된다. 저자 측정으로는 전체 학습 시간의 88% 이상이 storage 데이터 전송에 소비된다.
Original §I, p.1
According to our study, more than 88% of the total training time is consumed by transferring data from/to the storage. At a glance, combining multiple storage devices using RAID0 solution could alleviate the problem. However, such a method would fundamentally be bottlenecked by the limited number of PCIe lanes (or IO pins) of the host processor.
Main topic 핵심 통찰 — update 단계가 storage 대역폭 대부분 소비 + interconnect 병목 ▼
storage-offloaded 학습의 시간 대부분(>80%)은 update 단계에서 optimizer states를 올리고 내리는 데 쓰인다. 게다가 RAID0로 SSD를 늘려도 4개를 넘으면 공유 system interconnect(PCIe) 대역폭이 상한이라 speedup이 포화한다. 그래서 저자의 1차 목표는 '공유 interconnect를 통과하는 host↔storage 전송량 자체를 줄이는 것'이다.
Original §III, p.3
As we described in Section II, we break down the storage offloaded training into forward (FW), backward (BW + Gradients Offload), and update (Update + Optimizer states Upload/Offload). Contrary to conventional training, the most time is spent on the update phase of over 80% the training time, due to the storage access overhead.
Main topic SmartUpdate — update 연산을 CSD 내부 가속기로 이동 ((6+2)M→2M) ▼
핵심 아이디어: CPU가 하던 파라미터 update 연산을 CSD 안의 FPGA로 내려보낸다(SmartUpdate). 그러면 optimizer states(6M)를 host로 올릴 필요가 없어 interconnect 통과 트래픽이 (6+2)M에서 2M으로 줄고, 여러 CSD의 내부 대역폭을 합산해 쓸 수 있다. Adam 기준 총 8M read/write가 update 시 2M read(갱신 파라미터)+backward 시 2M write(gradient)로 축소된다.
Original §IV, p.4
we offload the update computation from the CPU to the accelerator in CSDs (SmartUpdate). From this, we can benefit from the fast aggregate bandwidth of CSDs, reducing the communication overhead of existing storage-offloaded LLM training methods from (6 + 2)M to 2M.
Main topic Internal Data Transfer Handler — buffer 사전할당 + swap overlapping (OOM 회피) ▼
SmartUpdate를 naive하게 짜면 tasklet마다 전체 메모리를 점유해 겹칠 수 없고, 억지로 겹치면 device OOM이 난다. 저자는 변수 buffer를 분리하고 급하지 않은 변수(momentum·variance)의 writeback을 지연시키는 handler를 제안한다. thread 0은 파라미터를 먼저 SSD로 쓰고, thread 1이 가장 큰 subgroup 크기로 사전할당된 같은 buffer를 재사용해 다음 로딩을 수행한다.
Original §IV-B, p.5
The key idea of the proposed handler is to separate the buffer for variables and lazily transfer non-urgent variables. ... Through the optimization, we obtain several benefits: 1) avoid reallocation of device memory, 2) the GPU can start forward/backward phases earlier, and 3) the data transfers to the SSDs are overlapped.
Main topic SmartComp — CSD-보조 gradient 압축 (multiple CSD의 새 병목 제거) ▼
SmartUpdate가 optimizer states 전송을 없애도 gradient(2M)는 여전히 공유 interconnect를 지나므로, CSD 수가 늘면 이게 새 병목이 된다. SmartComp는 GPU에서 gradient를 magnitude 기반 Top-K로 압축해 c%×2M만 보내고, CSD의 FPGA가 decompress한 뒤 update한다. DNN 학습이 gradient 오차에 관대하다는 점을 이용(기본 압축비 2%).
Original §IV-C, p.5
SmartUpdate reduces a significant amount of the SSD traffic by removing the transfer of optimizer states to the host. Given multiple CSDs in the system, the optimizer states (6M) are transferred within the CSDs through the internal bandwidth linearly scaled by the number of CSDs. However, gradients (2M) still go through the system interconnect, which becomes a new bottleneck when the number of CSDs increases.
Main topic Multiple CSD 워크로드 분배 — flatten + element-wise (architecture-agnostic) ▼
여러 CSD로 확장하는 방법: optimizer state 갱신이 전부 element-wise 연산이므로, 모델 파라미터를 1차원으로 flatten해 CSD들에 균등 분배한다. 각 CSD가 자기 몫 파라미터를 소유하고, backward 후 생성된 gradient를 소유 CSD로 offload해 P2P로 update한다. flatten 덕분에 분배가 모델 구조(layer·hidden dim·head 수)와 무관해 채택이 간단하다.
Original §IV-D, p.6
Because of using flattened model parameters, the distribution procedure is agnostic to the model architecture. This allows for a simple adoption of Smart-Infinity, where end users do not need to consider the model architecture information such as the layers, hidden dimensions, or number of heads.
Main topic Accelerator 구조 — General Updater(Adam AXPBY) + Top-K Decompressor ▼
FPGA 안 microarchitecture: updater는 여러 PE로 subgroup 단위 파라미터를 병렬 갱신하며, 핵심은 SIMD AXPBY 유닛(두 벡터를 계수 α·β로 곱해 더하는 general averaging)이다. 계수만 바꾸면 다양한 moving average를 표현해 SGD·AdaGrad·AdamW로 확장된다. decompressor는 Top-K 값을 index 위치로 '라우팅'만 하면 되어 산술 연산이 거의 없다(FPGA 자원 절약).
Original §V-A, p.7
Therefore, we placed SIMD AXPBY units, which can handle general averaging operations. It takes two input vectors (i.e., A and B) and multiplies the dedicated coefficients (i.e., α and β) to them. ... Note that the updater can be extended to other optimizers such as SGD, AdaGrad, and AdamW because most optimizers use variations of moving averaging.
Main topic Implementation — DeepSpeed + OpenCL + pybind11 (ready-to-use) ▼
실제 시스템 통합: DeepSpeed ZeRO-Infinity의 파라미터 update 부분을 대체하는 callable module로 구현하고, distutils로 C/C++ 모듈을 붙였다. Xilinx OpenCL 확장(CL_MEM_EXT_PTR_XILINX)으로 FPGA-SSD 버퍼를 잇고, pread/pwrite system call로 SmartSSD 내부 P2P를 구동, pybind11로 torch.Tensor를 C++에 노출한다. 옵션만 지정하면 DeepSpeed 엔진 초기화 시 자동 컴파일되어 기존 코드를 무수정 실행.
Original §VI, p.8
Because of this, Smart-Infinity can be enabled by simply specifying an option, and automatic compilation starts when the DeepSpeed engine is initialized. This indicates that any LLM training codes implemented with DeepSpeed can be run with Smart-Infinity with no modification, making Smart-Infinity a practical and powerful framework.
Main topic Evaluation — 최대 2.11× speedup, 대형 모델 확장성, 정확도 유지 ▼
SmartSSD(4TB NVMe + Kintex UltraScale+ KU15P FPGA) 최대 10개로 실측. SU+O+C가 baseline 대비 1.85×~1.98×(10 SSD), A100에서 최대 2.11× speedup. GPT-2 33B에서도 1.37×(6 SSD)·1.88×(10 SSD)로 확장성 유지. BLOOM·ViT 1.32×~1.85×. SmartUpdate는 baseline과 알고리즘적으로 동일해 정확도가 정확히 같고, SmartComp도 comparable. updater throughput은 7GB/s 이상으로 SSD read/write보다 빠르다.
Original §VII-C, p.10
SmartComp provides 1.22×∼1.31× additional speedup over SmartUpdate, showing 1.85×∼1.98× speedup over the baseline. Through the breakdown results, we can find out that SmartComp successfully reduces the remaining gradient offloading time of the optimized SmartUpdate further.
Main topic 결론 & feasibility 관점 — off-the-shelf 실물로 '가능함'을 증명 ▼
Smart-Infinity는 각 CSD의 FPGA 가속기로 storage-offloaded LLM 학습의 전송 병목을 없애는 CSD 기반 프레임워크다. 전용 die를 가정하고 시뮬레이터로만 검증한 선행(GradPIM·OptimStore)과 달리, off-the-shelf 제품(SmartSSD)만으로 PyTorch에 완전 통합된 ready-to-use 실물이라는 점이 핵심 — 곧 feasibility-by-building의 대표 사례.
Original §X, p.13
We propose Smart-Infinity, a novel CSD-based framework to accelerate storage-offloaded LLM training. ... Smart-Infinity has been fully integrated into PyTorch only with off-the-shelf products, making itself a ready-to-use solution.
Claim 학습 시간의 88%+가 storage 데이터 전송 ▼
storage-offloaded 학습의 근본 문제를 수치로 못박은 문장. 병목이 compute가 아니라 data movement임. RAID0로 SSD를 합쳐도 host PCIe lane 수가 상한이라 근본 해결이 안 됨.
Original §I, p.1
According to our study, more than 88% of the total training time is consumed by transferring data from/to the storage.
Question 왜 storage-offloaded인가? (배경) ▼
GPU 메모리에 optimizer states까지 다 못 올리므로, ZeRO-Infinity류는 optimizer states·gradients를 host memory와 SSD로 내보내 GPU 용량 벽을 넘는다. FP16 파라미터 크기를 M이라 할 때 mixed precision Adam의 optimizer states(파라미터·momentum·variance FP32)가 6M을 차지하는 게 핵심 부담.
Original §II-A, p.2
The FP32 optimizer states occupy 6M capacity (model parameter, momentum, and variance in FP32) under mixed precision training, regarding the FP16 model parameter size as M.
Result Fig 3a — update 단계가 학습 시간의 >80% ▼
ZeRO-Infinity baseline을 FW / BW+Grad Offload / Update+Opt Upload·Offload 세 구간으로 쪼갠 breakdown. 모델 크기(2.5B~20.5B) 무관하게 update 구간이 압도적(>80%) → 여기를 없애는 게 최대 이득 지점.
Original §III, p.3
Contrary to conventional training, the most time is spent on the update phase of over 80% the training time, due to the storage access overhead. The data transfer portion is significant regardless of model sizes, so it is a critical issue to be addressed in storage-offloaded LLM training.
Result Fig 3b — RAID0 SSD 확장은 4개에서 포화 ▼
SSD를 RAID0로 늘려 대역폭을 키우는 소박한 해법의 한계 실측. 4개를 넘으면 공유 system interconnect(PCIe)가 상한이라 speedup이 포화 → 'SSD를 더 꽂는다'로는 못 푸는 문제. SmartUpdate가 interconnect를 우회(내부 대역폭 합산)해야 하는 이유.
Original §III, p.3-4
Figure 3(b) shows the normalized speedup of storage-offloaded training when increasing the number of SSDs using RAID0. Unfortunately, the speedup saturates after using more than four SSDs. Shared system interconnect becomes a new bottleneck when using more than four SSDs.
Claim 1차 목표 = 공유 interconnect 통과 전송량 최소화 ▼
논문 전체를 관통하는 설계 목표. 문제를 '연산을 빠르게'가 아니라 '공유 interconnect를 지나는 host↔storage 전송량을 줄인다'로 규정 → SmartUpdate(optimizer states 제거)·SmartComp(gradient 압축)가 모두 이 목표의 파생.
Original §III, p.4
our primary goal is minimizing the data transfer between storage devices and host memory through the shared system interconnect, and we need to fully utilize 1) the aggregated internal bandwidth from multiple CSDs and 2) the computational ability of the accelerator in each CSD.
Method Table I — 통신량 (6+2)M → 2M ▼
Adam 기준 interconnect 트래픽 표. baseline(ZeRO-Inf)은 optimizer states 6M+6M, gradient 2M+2M. SmartUpdate는 update를 CSD 내부로 옮겨 optimizer states 통신을 없애고, update 시 2M read + backward 시 2M write만 남긴다. SmartComp는 gradient write를 c%×2M으로 더 줄임.
Original §IV-A, p.4
SmartUpdate minimizes the total communication volume through the system interconnect to only 2M read during the update phase for the updated parameters and 2M write during backward for the gradients.
Claim 핵심 = CSD 개수 확장 시 내부 대역폭 합산 ▼
SmartUpdate의 진짜 이득은 CSD를 늘릴 때 나온다. 단일 CSD면 병목이 interconnect에서 CSD 내부 스위치로 옮겨질 뿐이지만, CSD가 늘면 FPGA-SSD 내부 대역폭이 선형 증가(공유 interconnect는 고정)해 전체 speedup을 견인. → 'aggregate internal bandwidth'가 Smart-Infinity의 원동력.
Original §IV-A, p.4-5
When SmartUpdate is used with a single CSD, the bottleneck simply moves from the system interconnect to the CSD-internal switch. However, the real advantage appears when scaling the number of CSDs. When the number of CSDs increases, the aggregate bandwidth between the FPGA and SSD increases linearly, while that of the system interconnect (PCIe) to the host stays constant.
Method 2-thread buffer 재사용 + 지연 writeback ▼
thread 0/1이 CPU에서 buffer를 관리. thread 0이 update를 마치면 GPU가 곧 필요로 하는 파라미터를 먼저 SSD로 쓰고, 급하지 않은 momentum·variance의 writeback은 미룬 뒤 thread 1에게 다음 subgroup 로딩을 넘긴다. buffer는 가장 큰 subgroup 크기로 사전할당되어 재사용 → 재할당·OOM 없이 전송을 겹침.
Original §IV-B, p.5
Thus, thread 0 defers the writeback of the remaining variables and signals thread 1 to start loading the model parameters of the next subgroup. Because we have preallocated the buffer for the largest subgroup size, thread 1 can directly reuse the same buffer.
Claim naive overlap은 OOM → handler가 3가지 이득 ▼
subgroup 간 전송을 소박하게 겹치면 P2P용 추가 device memory가 필요해 OOM이 난다. handler는 이를 피하면서 ① device memory 재할당 회피, ② GPU가 forward/backward를 더 일찍 시작, ③ SSD로의 전송을 overlap — 세 이득을 동시에 얻는다.
Original §IV-B, p.5
Through the optimization, we obtain several benefits: 1) avoid reallocation of device memory, 2) the GPU can start forward/backward phases earlier, and 3) the data transfers to the SSDs are overlapped.
Method magnitude 기반 Top-K: GPU 압축 / FPGA 복원 ▼
역할 분담이 영리하다. 무거운 작업(sort로 상위 magnitude gradient 선택)은 강력한 GPU가, 가벼운 작업(index에 따라 값을 흩뿌리는 scatter=decompress)은 CSD의 lightweight FPGA가 맡는다. 압축 결과는 index 리스트 + value 리스트. 낮은 magnitude gradient는 0으로 대체(update 방향에 영향 작음).
Original §IV-C, p.6
This is a viable choice because the relatively heavier job or sorting can be done in powerful GPUs, and the lightweight FPGAs in CSD perform the decompression part that only involves scattering the values according to the index.
Claim gradient가 multiple CSD의 새 병목 → 압축이 정당 ▼
SmartUpdate로 optimizer states 통신은 사라지지만, gradient(2M)는 여전히 공유 interconnect를 지나 CSD 수가 늘면 지배적 병목이 된다. DNN 학습이 gradient 오차에 관대하고(gradient compression은 분산 학습의 사실상 표준), FPGA read가 write보다 빠르다는 점이 압축을 SmartComp로 정당화.
Original §IV-C, p.5
It is widely known that DNN training is tolerable to some degree of errors, especially the gradients. Gradient compression methods are widely used to mitigate communication overhead in neural network training, and it is almost a norm to train modern larger models in distributed settings.
Method flatten → 균등 분배 → P2P element-wise update ▼
모델 파라미터를 1차원으로 펼쳐 CSD들에 균등 분배하고, 각 CSD가 소유 파라미터(index i×D ~ (i+1)×D-1)를 담당. backward 후 gradient를 소유 CSD로 offload하면 그 CSD의 FPGA-SSD가 P2P로 update. optimizer state 갱신이 전부 element-wise이므로 이런 평면 분배가 성립.
Original §IV-D, p.6
Using this, Smart-Infinity flattens the model parameters and equally distributes them to the CSDs, where each CSD takes the responsibility to update the owned parameters. Then, the optimizer states are allocated and initialized at CSDs that own the associated parameters.
Claim 분배가 모델 구조와 무관 → 채택 단순 ▼
flatten 덕분에 CSD 분배가 layer·hidden dim·head 수 같은 아키텍처 정보에 의존하지 않는다. 사용자는 모델 구조를 신경 쓸 필요 없이 붙일 수 있어, 임의의 transformer 계열에 범용 적용 가능(BLOOM·ViT까지 되는 근거).
Original §IV-D, p.6
Because of using flattened model parameters, the distribution procedure is agnostic to the model architecture. This allows for a simple adoption of Smart-Infinity, where end users do not need to consider the model architecture information such as the layers, hidden dimensions, or number of heads.
Method SIMD AXPBY 유닛 = general averaging (optimizer 범용) ▼
updater는 두 입력 벡터에 계수 α·β를 곱해 더하는 SIMD AXPBY 유닛으로 구성. 계수만 바꾸면 momentum·variance 등 다양한 moving average를 표현하므로 Adam뿐 아니라 SGD·AdaGrad·AdamW로 확장된다(대부분 optimizer가 moving average 변형이라는 통찰). subgroup(가속기 DRAM 크기 D) 단위 병렬 처리.
Original §V-A, p.7
The above procedure can be used for various averaging operations by changing the coefficients. ... Note that the updater can be extended to other optimizers such as SGD, AdaGrad, and AdamW because most optimizers use variations of moving averaging.
Method Top-K decompressor = 산술 없는 index 라우팅 ▼
decompressor는 compressed gradient의 (index, value) 쌍을 읽어 gradient buffer의 해당 위치에 값을 채우고 나머지는 0으로 둔다. 곱셈·덧셈 없이 '값을 올바른 위치로 라우팅'만 하므로 FPGA 자원 소모가 작다(LUT 여유 → 추가 확장 여지). Adam은 full matrix가 필요해 update 전에 먼저 decompress.
Original §V-B, p.7-8
In the output vector, the partial Top-K elements of the target parameters selected in this iteration j are filled with their values, and the others are filled with zero. Until decompression finishes, the decompressor repeats.
Method DeepSpeed 대체 모듈 + OpenCL P2P + pybind11 ▼
DeepSpeed ZeRO-Infinity의 파라미터 update만 교체하는 callable module. Xilinx OpenCL 확장의 CL_MEM_EXT_PTR_XILINX로 FPGA-SSD 버퍼를 잡고, pread/pwrite로 SmartSSD 내부 P2P를 구동, pybind11로 torch.Tensor를 C++에 노출. gradient offload 경로를 해당 SSD로 향하게 조정. 옵션 지정만으로 활성화 → 무수정 적용.
Original §VI, p.9
We use pread/pwrite system call to the P2P buffer, which operates the direct internal P2P communication feature of SmartSSD.
Result speedup — 최대 2.11× (A100), 1.85~1.98× (10 SSD) ▼
SU(SmartUpdate)→SU+O(handler)→SU+O+C(SmartComp) 순으로 누적 향상. SU+O+C가 baseline 대비 1.85×~1.98×(10 SSD). GPT-2 8.4B·6 SSD에서 baseline update가 학습 시간의 75.57%를 차지하던 것을 제거. 연산 비중이 작은 고급 GPU(A100)에서 전송 절감 효과가 커져 최대 2.11×.
Original §VII-C · §VII-E, p.10-11
In GPT-2 8.4B model with 6 SSDs, the update time with the optimizer states communication time consumes 75.57% of the training time of the baseline. ... provides up to 2.11× speedup in the A100 GPU setting.
Result 대형 모델 확장성 — GPT-2 33B에서 1.88× ▼
16.6B~33.0B로 키워도 speedup이 유지·증가. GPT-2 33.0B에서 baseline 대비 1.37×(6 SSD)·1.88×(10 SSD). transformer의 통신량이 파라미터 수에 비례하고 CSD를 더 쓸수록 큰 모델에도 speedup을 주므로 확장성이 있다(반면 baseline은 업/다운로드 오버헤드로 고통).
Original §VII-D, p.10
Even with GPT-2 33.0B model, Smart-Infinity provides 1.37× and 1.88× speedup over the baseline using 6 SSDs and 10 SSDs, respectively.
Result 정확도 — SmartUpdate는 baseline과 완전 동일 ▼
핵심 신뢰성 근거. SmartUpdate는 baseline과 알고리즘적으로 동일해 정확도가 정확히 같다(연산 위치만 CPU→FPGA로 옮겼을 뿐). SmartComp는 lossy 압축이지만 GLUE(MNLI·QQP·SST-2·QNLI) 파인튜닝에서 baseline과 comparable → 속도 이득이 정확도를 희생하지 않음.
Original §VII-J, p.12
SmartUpdate is algorithmically identical to the baseline training, so the accuracy is exactly the same as the baseline. SmartComp adopts lossy compression, but achieves comparable accuracy in all datasets.
Result throughput·비용 — updater >7GB/s, GFLOPS/$ 증가 ▼
updater throughput이 7GB/s 이상으로 SSD read/write보다 충분히 높아 SSD가 병목을 결정(가속기가 발목 안 잡음). 비용 효율(GFLOPS/$)은 SmartSSD가 일반 SSD보다 6× 비싸 1~3 CSD에선 baseline보다 낮지만, 4개 초과부터 speedup이 커져 역전되고 CSD를 늘릴수록 계속 증가.
Original §VII-H · §VII-I, p.11-12
The throughput of the updater is above 7GB/s, which is sufficiently higher than the SSD read/write. ... When scaling the number of SmartSSDs, the GFLOPS/$ keeps increasing, showing the efficiency of Smart-Infinity.
Result 일반성 — 다른 optimizer·모델에도 성립 ▼
SGD·AdaGrad로 바꿔도 speedup 유지(SGD는 optimizer state가 3/4 적어 이득이 약간 작음). BLOOM·ViT에서도 1.32×~1.85×로 GPT-2·BERT와 유사 → 특정 모델/optimizer에 종속되지 않는 범용 가속. AXPBY 유닛 + flatten 분배가 이 일반성의 구조적 근거.
Original §VII-G, p.11
On such models, Smart-Infinity stably shows 1.32×∼1.85× speedup, similar to the results we have shown for GPT-2 and BERT.

Gap / Idea 한계 — upstream 전송 병목 / 단일 CSD 손해 / PCIe topology 의존 ▼
저자 스스로 밝힌 gap: (1) 현재 병목은 CSD→host로 올라가는 갱신 파라미터(upstream) 전송 — 모델 압축(quantization/pruning)과 결합해 압축된 모델을 올리면 더 줄일 여지. (2) 단일 CSD에서는 대역폭 증가가 없고 FPGA 사용 오버헤드로 오히려 소폭 느려짐. (3) speedup이 PCIe topology(multi-GPU congested)에 따라 달라짐.

Ext. reference 선행 대비 — 시뮬레이터(GradPIM·OptimStore)와의 차별 ▼
관련 연구 중 GradPIM·OptimStore도 DNN 학습을 near-data로 가속하지만, 전용 memory/storage die를 가정하고 시뮬레이터로만 검증해 real-system 통합 이슈를 다루지 않는다. Smart-Infinity는 '여러 CSD를 실제로 써서 interconnect 병목을 푼 최초 연구'라고 주장 → 이 real-system·multi-CSD 실증이 feasibility 관점의 차별점.
Original §IX-A, p.13
It is worth noting GradPIM [57] and OptimStore [58] as they both target DNN training similar to this work. However, they assume dedicated memory/storage die, making those solutions less practical. Moreover, they were only implemented on simulators and do not consider real system integration issues. ... Smart-Infinity is the first work using multiple CSDs to mitigate system interconnect bottlenecks in DNN training.
