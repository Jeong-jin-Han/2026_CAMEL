Main topic 문제 — GPU memory wall
모델이 3년간 1000배 커지는 동안 GPU 메모리는 5배(16→80GB)뿐 → 극단 규모는 여러 GPU의 aggregate memory에 억지로 맞추는 3D parallelism(data+model+pipeline)이 필요해 복잡·비쌈. ZeRO-Infinity는 GPU+CPU+NVMe 이질적(heterogeneous) 메모리로 이 벽을 넘음 — model code 리팩터링 없이.
Original §Abstract, p.1
the largest dense deep learning models have grown over 1000x ... while the GPU memory has only grown by 5x (16 GB to 80 GB).
Result 대역폭 요구 vs 단일 PCIe
offload가 실용적이려면: parameter·gradient $>70$ GB/s, optimizer state $>1.5$ TB/s, activation $1$~$4$ GB/s. 그런데 단일 GPU↔CPU/NVMe PCIe는 $\approx 12$ GB/s뿐 → 그대로는 턱없이 부족 → 병렬화(bandwidth-centric)가 필요.
Original §5.2, p.5
the bandwidth must be greater than 70GB/s, 1.5TB/s, and 1-4 GB/s ... a meager 12 GB/s PCIe bandwidth from a single GPU to CPU memory or NVMe ... is simply not sufficient
Method ZeRO-3 배경 (모든 model state 분할)
ZeRO는 data-parallel의 메모리 중복 제거 최적화. ZeRO-1/2/3 = optimizer state / +gradient / +parameter를 DP rank들에 분할(partition). ZeRO-Infinity는 ZeRO-3 위에 세워짐(모든 model state 분할).
Original §5.1.1, p.5
ZeRO-Infinity is built on top of ZeRO-3 which partitions all model states to remove memory redundancy.
Method Infinity offload engine
ZeRO-3로 분할된 모든 model state를 CPU 또는 NVMe로 offload(또는 GPU 유지), 메모리 요구에 따라 배치. NVMe는 GPU 메모리의 50배↑ → 96노드(1536 GPU) NVMe에 100T 모델 state도 수용. activation checkpoint도 CPU로 내림.
Original §5.1.1, p.5
the infinity offload engine which can offload all of the partitioned model states to CPU or NVMe memory, or keep them on the GPU based on the memory requirements.
Method ★ Bandwidth-centric partitioning
기존 ZeRO/Offload는 파라미터를 한 DP가 소유·broadcast → PCIe 하나만 활성. ZeRO-Infinity는 파라미터를 전 DP에 분할하고 allgather → 모든 PCIe가 병렬로 각 $1/dp$ 전송 → CPU/NVMe→GPU 유효 대역폭이 $dp$(device 수)에 선형 비례.
Original §6.1, p.6
all PCIe links are active in parallel, each bringing in 1/dp portion of the parameter ... the effective communication bandwidth between NVMe or CPU to the GPU, increases linearly with the dp degree.
Claim broadcast(1 PCIe) vs allgather(전 PCIe)
broadcast: 파라미터를 소유 GPU로 먼저 옮겨야 해서 PCIe 하나만 활성, 나머지 idle. allgather: 전 DP가 각자 자기 몫을 병렬로 → 전 PCIe 동시. GPU-only면 data 이동량 같아 무의미하나, offload(NVMe/CPU) 상황에선 game changer.
Original §6.1, p.6
only a single PCIe can be active for this process, while all the PCIe links connected to all the other GPUs are idle.
Method Memory-centric tiling
큰 operator(예: 대형 linear)를 수학적으로 동등한 작은 tile들의 순차 실행으로 바꿈. ZeRO-3의 fetch/release로 tile 하나씩 가져오고 놓음 → working memory가 tile 수에 반비례 감소 → 임의 크기 layer를 model parallelism 없이 처리.
Original §5.1.3, p.5
breaking down a large operator into smaller tiles that can be executed sequentially ... ZeRO-Infinity can support operators of arbitrary sizes, without relying on model parallelism
Memo "block 어떻게 쪼개나"의 답
Smart-Infinity가 상술 안 한 'block 분할'의 답이 여기: block = layer 단위, 큰 layer는 memory-centric tiling으로 tile로 더 쪼갬. 크기는 working memory(GPU)에 맞춤. (Smart-Inf의 subgroup = 이 발상의 update-단계·FPGA DRAM 판)
Original
Method Overlap-centric (dynamic prefetcher)
dynamic prefetcher가 연산 순서를 그때그때 추적 → i번째 실행 중 i+1/i+2/i+3에 필요한 3단계 전송(NVMe→CPU, CPU→GPU, GPU→GPU)을 미리·병렬로. backward는 gradient reduce-scatter/offload를 연산과 overlap. temporary buffer 재사용으로 fragmentation↓.
Original §6.2, p.6~7
before executing the i operator, the prefetcher can invoke nc, cg, and gg-transfer for parameters required by i+3, i+2, and i+1 operators
Method Ease of use (리팩터링 불필요)
자동 data movement: PyTorch submodule에 pre/post forward-backward hook → 쓰기 직전 allgather, 직후 partition/offload. 자동 model partitioning at init: 모듈 생성자 wrap → 초기화 즉시 분할·offload, 전체 모델이 한 프로세스에 통째로 안 올라감 → 수동 리팩터링 불필요.
Original §5.3 / §7, p.7
automated data movement to gather and partition parameters right before and after they are required ... automated model partitioning during initialization
Result Evaluation
32조 파라미터(3D parallelism ~650B 대비 50배). 512 GPU 최대 20T at $34$~$49$ TFlops/GPU. 1T에서 64→512 GPU superlinear. 단일 노드(16 GPU)로 ≤100B를 $>40$ TFlops/GPU(GPT-3급 DGX-2 1대 fine-tuning=민주화). tiling으로 hidden 8K→64K. ZeRO-Offload 대비 64 GPU에서 약 2배.
Original §8.2, p.8
ZeRO-Infinity trains models over 32 trillion parameters compared to about 650B parameters with 3D parallelism ... a leap of 50x
Claim 결론 & Smart-Infinity 연결
이질적 메모리(GPU+CPU+NVMe)로 memory wall 초월, 리팩터링 없이 규모·민주화. ★ 단 update는 여전히 host CPU(NVMe→CPU로 올려 처리). Smart-Infinity가 이 update를 CSD FPGA로 옮겨 그 traffic을 제거. bandwidth-centric partitioning($dp$ 비례) ↔ Smart-Inf aggregate internal bandwidth(CSD 수 비례) = 같은 발상.
Original (종합, §9)
Memo 내 연구 연결 (CXL/disaggregation)
bandwidth-centric partitioning의 '대역폭이 device 수에 비례'는 CXL/disaggregation의 'per-device path 병렬 합산'과 대응. shared fabric(고정) vs per-device path(확장) 구도 = 내 memory-system 연구의 핵심 축. Smart-Inf는 그 확장을 CSD 내부 P2P로 실현.
