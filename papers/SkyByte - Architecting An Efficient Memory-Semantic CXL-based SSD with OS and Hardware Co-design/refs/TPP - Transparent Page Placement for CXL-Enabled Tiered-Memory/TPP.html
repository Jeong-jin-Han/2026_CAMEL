Main topic Killer Application
TPP가 푸는 문제: CXL-Memory가 OS에 CPU-less NUMA node로 보이는 tiered-memory에서, application 수정·사전지식 없이 hot page는 빠른 local memory에, cold page는 느린 CXL-Memory에 두는 OS-level 투명 페이지 배치(transparent page placement)를 kernel 안에서 실현하는 것.

Killer application 1 — hot page가 느린 tier에 갇히는(trapped) 문제 해결: 기본 Linux는 page의 active 상태를 안 보고 즉시 promote해 왕복(ping-pong)을 만들고, 동기 reclamation이 새 할당을 CXL로 밀어낸다. TPP는 이 두 병목을 없애 hot을 local에 유지.

Killer application 2 — 경량·범용 온도 감지: 무거운 PEBS/IPT 대신 minor page fault + kernel LRU로 거의 zero-overhead, page-size agnostic 온도 감지.

Killer application 3 — production 배포 가능성: Meta 4개 workload를 FPGA CXL 1.1 실기에서 검증, 패치 대부분이 Linux v5.18에 머지 — 커널 릴리스로 전역 배포 가능.

결과: all-local ideal baseline과 <1% gap, default Linux 대비 최대 18%, NUMA Balancing·AutoTiering 대비 5-17% 개선.
Original Abstract, p.1
We propose a novel OS-level application-transparent page placement mechanism (TPP) for CXL-enabled memory. TPP employs a lightweight mechanism to identify and place hot/cold pages to appropriate memory tiers.
Main topic 필요한 이유 (Why It's Needed)
메모리는 Meta rack의 TCO 최대 33.3% · power 37.1%로 커졌고(Fig.3), homogeneous 서버 설계는 CPU-memory 강결합 탓에 세대·용량·대역폭이 경직돼 stranded 자원을 낳는다.

CXL[7]은 이를 풀어 DRAM-like 대역폭 + cache-line granular 접근의 중간 지연 tier(DRAM 대비 $+50\text{-}100$ns, $\approx 170\text{-}250$ns)를 만든다 — SW엔 CPU-less NUMA node로 보인다.

그런데 Linux 메모리 관리는 동종 DRAM-only 전제라 CXL tier에서 부진하다. 두 근원:

(1) 동기 reclamation: local node가 차면 reclamation(swap page-out)이 critical path에서 돌고, 느린 그 동안 새 allocation이 CXL-node로 몰려 영구 정착.

(2) trapped hot pages / ping-pong: 기본 NUMA Balancing이 active 상태 확인 없이 즉시 promote $\rightarrow$ hot page가 CXL에 갇히거나 왕복.

datacenter workload는 2분 내 할당의 55-80%가 idle이라 tiering 여지는 충분하다.
Original §1, p.1-2
Linux's memory management mechanism is designed for homogeneous CPU-attached DRAM-only systems and performs poorly on CXL-Memory system.
Main topic 해결책 (Solution)
TPP는 'hotter' page를 local에, 'colder' page를 CXL-Memory에 두는 kernel-space 메커니즘. 설계공간 4축(§5) + 저비용 온도 감지(§4):

(a) 경량 demotion(§5.1): reclamation 후보를 swap 대신 별도 demotion list로 모아 CXL-node로 비동기 migration(swapping보다 수 order 빠름). inactive부터 스캔.

(b) Alloc/Reclaim 분리(§5.2): 'reclamation 정지' watermark와 '새 allocation' watermark를 분리 — free가 demotion_watermark까지 background reclaim, 새 allocation은 allocation_watermark만 넘으면 진행 $\rightarrow$ local에 free headroom 유지.

(c) Active-LRU promotion(§5.3): NUMA Balancing 증강, CXL-node만 sampling. faulted page가 active LRU에 있을 때만 promote $\rightarrow$ ping-pong에 hysteresis 부여.

(d) Page-type-aware allocation(§5.4): file cache/tmpfs는 CXL 우선, anon은 local 선호.

온도 감지(§4): PEBS/IPT 대신 minor page fault + LRU로 page-size agnostic·저오버헤드.
Original §5, p.7
TPP places 'hotter' pages in local memory and moves 'colder' pages in CXL-Memory. TPP's design-space can be divided across four main areas – (a) lightweight demotion to CXL-Memory, (b) decoupled allocation and reclamation paths, (c) hot-page promotion to local nodes, and (d) page type-aware memory allocation.

Main topic 결론 (Conclusion)
TPP는 CXL-Memory를 한 host의 CPU-less NUMA node로 보는 tiered-memory에서, 사전지식 없이 hot/cold를 투명하게 배치하는 OS-level 메커니즘이다. 경량 demotion·alloc/reclaim 분리·active-LRU promotion·page-type-aware allocation으로 all-local ideal에 근접(<1%), SOTA 대비 5-17% 개선하며 Linux v5.18에 머지돼 실전 배포된 첫 end-to-end CXL-Memory 시스템으로 자평.

의의: OS/software 쪽 transparent placement의 대표작. [[SkyByte]](HPCA'25)는 같은 hot/cold 배치를 디바이스 하드웨어에서 하며, 그 대조군 SkyByte-CT가 바로 TPP류 OS baseline.

한계 / 열린 질문: (1) single-host local↔CXL만 다룸 — CXL tier가 여러 host에 공유(pooling)되면 per-host 온도 모델이 깨짐. (2) promotion이 만든 로컬 사본이 공유 시 다른 host에 stale를 노출(cross-host invalidation 부재). (3) multi-tenant QoS·bandwidth-expansion은 future로만 언급.

we design TPP, an OS-level transparent page placement mechanism that works without any prior knowledge on applications' memory access behavior.

- 재접근: Web은 cold의 80%가 10분 내 재접근 $\rightarrow$ 무작위 offload 위험 $\rightarrow$ promotion 필요.
- 동적성: (de)alloc으로 hot↔cold가 빠르게 뒤집힘 $\rightarrow$ 정적 배치는 성능 악화.

Claim Trapped hot pages · ping-pong: default Linux의 핵심 병목
TPP 동기의 심장. 기본 Linux의 두 결함:

(1) 동기 reclamation이 CXL로 밀어냄: local이 차면 reclamation이 swap page-out을 critical path에서 수행 $\rightarrow$ 느려서 그 동안 새 allocation이 CXL-node로 몰려 영구 정착. Web1에서 default는 local 비우기가 TPP보다 44× 느림.

(2) 상태 무시 promotion $\rightarrow$ ping-pong: NUMA hint fault 시 default NUMA Balancing이 page의 active 상태를 안 보고 즉시 promote $\rightarrow$ 드물게 쓰는 page도 올라가 곧 demotion 후보가 되는 왕복. 반대로 promotion이 아예 없으면 hot page가 CXL에 영영 갇힘(trapped).

결과: default Linux는 hot의 22-25%를 CXL에 가둬 avg 지연 7×, throughput loss 2.2-2.8×(vs TPP).
Original §5.3, p.8
When a NUMA hint fault happens on a page, default NUMA balancing instantly promotes the page without checking its active state.

Method §5.1 경량 demotion: swap이 아닌 async migration
local node가 차면 기본 reclamation은 swap으로 page-out $\rightarrow$ 느려서 그 동안 새 allocation이 CXL-node로 몰린다.

TPP는 reclamation 후보를 swap 대신 별도 demotion list에 넣어 CXL-node로 비동기 migration한다 — NUMA node로의 migration은 swapping보다 수 order 빠르다. demoted page는 여전히 in-memory라 load/store로 접근 가능(swap의 major fault 회피).

inactive page부터 스캔해 hot page가 실수로 내려갈 확률을 낮춤. migration 실패(예: CXL-node 저메모리) 시 기본 reclamation으로 fallback. 다중 CXL-node면 CPU 거리 기반 static 선택으로 충분.
Original §5.1, p.7
instead of invoking swapping mechanism, we put them into a separate demotion list and try to migrate them to the CXL-node asynchronously.
Method §5.2 Alloc/Reclaim 분리: watermark로 free headroom 유지
Linux는 zone별 min/low/high watermark를 둔다. free가 low 아래면 reclamation 시작 + 새 allocation은 high 채울 때까지 정지(halt) $\rightarrow$ 고할당률에서 reclamation이 못 따라가 CXL로 page가 몰린다.

TPP는 'reclamation 정지'와 '새 allocation 발생' 로직을 분리:

$$demotion\_watermark > allocation\_watermark > low\_watermark$$

- free가 demotion_watermark에 닿을 때까지 background reclamation을 계속 돌린다.
- 새 allocation은 allocation_watermark만 만족하면 진행.
- 항상 더 많이 reclaim해 local에 free headroom 유지 $\rightarrow$ (1) 짧고 뜨거운 새 할당을 local에 직접, (2) CXL의 trapped hot page promotion 수용.

공격성은 /proc/sys/vm/demote_scale_factor(기본 2%)로 조절. 효과: local allocation rate 95%tile 1.6×.
Original §5.2, p.8
we decouple the logic of 'reclamation stop' and 'new allocation happen' mechanism. We continue the asynchronous background reclamation process on local node until its total number of free pages reaches demotion_watermark, while new allocation can happen if the free page count satisfies a different watermark – allocation_watermark.
Method §5.3 Active-LRU promotion: ping-pong에 hysteresis
압박으로 CXL에 간 page나 나중에 hot 된 demoted page를 안 올리면 hot이 CXL에 갇힌다(trapped). TPP는 NUMA Balancing을 증강 — kernel task가 각 node의 일부(기본 256MB)를 샘플, remote 접근 시 NUMA hint fault로 promote. 단 local의 hot을 옮기는 건 무의미하므로 CXL-node만 sampling(hint fault 오버헤드 절감).

Ping-pong 해결: faulted page의 LRU age를 본다 — active LRU에 있을 때만 promotion 후보(무조건 promote 금지). inactive면 accessed 표시 후 active로 옮기고 다음 hint fault 때 승격 $\rightarrow$ hysteresis 부여. anon/file 별도 LRU라 type별 promotion rate 차등 $\rightarrow$ 수렴 가속.

효과: promotion rate 11×↓, demote-후-재promote 50%↓, promotion 성공률 48%↑(수렴은 5분 더 소요).
Original §5.3, p.8
We consider the faulted page as a promotion candidate only if it is found in the active LRUs. This significantly reduces the promotion traffic.
Method §5.4 Page-type-aware allocation: file→CXL, anon→local
관측(Chameleon): anon이 file보다 뜨겁다. 그런데 production app은 warmup 중 file I/O로 잘 안 쓰이는 file cache를 많이 만들고, 이게 local을 점유해 anon을 CXL로 밀어낸다(나중에 promote 필요).

해결: 선택적 정책으로 file cache/tmpfs를 CXL-node에 우선 할당, anon은 local 정책 유지. hot 된 file cache는 promotion 후보가 되면 나중에 local로 올림.

효과: 작은 local + 크고 싼 CXL 구성에서도 all-local 성능 유지(Table 2): Web1 2:1 local 97%/throughput 99.5%, Cache1 1:4 85%/99.8%, Cache2 1:4 72%/98.5%.
Original §5.4, p.8
we allow an application allocating caches (e.g., file cache, tmpfs, etc.) to the CXL-nodes preferrably, while preserving the allocation policy for anon pages.
Method §4 온도 감지: minor page fault + LRU (PEBS 아님)
설계 3질문의 답 = kernel-space 구현 + 경량 온도 감지 + CXL을 main memory tier로(swap 아님).

왜 PEBS/IPT가 아닌가:
- PEBS: CPU 벤더 간 비표준, counter 제한, 상시 구동 부담 $\rightarrow$ TPP의 always-on 컴포넌트로 부적합.
- IPT/poisoning: accessed bit clear + TLB flush로 고빈도 감시 시 심한 slowdown.
- Thermostat[31]: 2MB huge-page 전용 $\rightarrow$ TPP 목표(page-size agnostic)에 안 맞음.

TPP의 선택:
- CXL-node의 hot 감지 = NUMA Balancing의 minor page fault(NUMA hint fault)만 활용 $\rightarrow$ 오버헤드 낮게.
- local node의 cold 감지 = Linux 기존 LRU로 충분(가상 zero-overhead).

(프로파일링 툴 Chameleon은 PEBS 기반이지만 이는 오프라인 특성화용이지 TPP의 런타임 경로가 아님.)
Original §4, p.6-7
when designing TPP, we chose to only leverage minor page fault as a temperature detection mechanism for CXL-Memory. As CXL-Memory is expected to hold warm and cold pages, this will keep the overhead of temperature detection low.

Gap / Idea 내 연구방향: single-host 전제 — multi-node coherence가 빈칸
TPP는 single-host tiered memory(한 host의 local↔CXL NUMA node)만 다룬다. page-temperature도, LRU도, watermark도, PG_demoted도 전부 단일 host 물리주소 공간 안 이야기다.

내 방향(multi-node CXL coherence)이 채울 빈칸: CXL tier가 여러 host에 공유(pooling)되는 순간 —
- 온도 모델 붕괴: page 온도가 host마다 달라 배치 결정이 충돌. minor page fault는 remote host의 접근을 못 봄.
- promotion의 stale 문제: host A가 hot page를 자기 local로 promote(사본 생성)하면 host B는 stale를 봄 $\rightarrow$ cross-host invalidation 필요(CXL 3.0 back-invalidate / HDM-DB). TPP엔 없음.
- 소유권: 공유 page의 demote/promote 권한을 누가 갖나?

즉 TPP의 '기법'(demotion·watermark·active-LRU)은 재사용하되 '문제 정의'를 single$\rightarrow$multi host로 다시 세우는 게 gap.
Question 왜 'trap이 hot page를 가두는가': instant promotion의 함정
default NUMA Balancing이 CXL 시스템에서 실패하는 근본 이유를 한 겹 더 파면:

기본 정책은 NUMA hint fault가 나면 active 상태 확인 없이 즉시 promote한다. CXL-node는 항상 압박 상태가 아니라, faulted page가 inactive LRU에 머물러 있어도 promotion 필터를 그냥 통과한다 $\rightarrow$ 드물게 쓰는 page까지 올라간다. 올라간 page는 곧 demotion 후보가 돼 다시 내려가는 ping-pong을 만들고, 이 불필요 트래픽이 local free space를 잠식해 진짜 hot page를 밀어낸다.

반대로 promotion을 아예 끄면 hot page가 CXL에 영영 갇힌다(trapped). 두 실패 사이의 좁은 길을 TPP는 active-LRU 필터 + inactive→active 승격 후 지연 promote(hysteresis)로 통과한다. 이 tension이 TPP §5.3의 존재 이유.
Original §5.3, p.8
Without any promotion mechanism, hot pages will always be trapped in CXL-nodes and hurt application performance.
Gap / Idea 공유 CXL tier에서 TPP의 온도/배치가 깨지는 지점
구체 시나리오로 gap을 못박으면 — host A·B가 같은 CXL memory pool을 공유한다.

1. 온도의 지역성 붕괴: A에겐 cold인 page가 B에겐 hot일 수 있다. TPP는 각 host가 자기 minor page fault로 온도를 재므로 한 host의 view만 반영 $\rightarrow$ A가 demote한 page를 B가 즉시 재접근.
2. promotion = 사본 = coherence 부담: A가 pool의 hot page를 자기 local DRAM으로 promote하면 물리 사본이 생긴다. 공유 전제에선 B가 그 page를 어떻게 보나? $\rightarrow$ directory/back-invalidate(CXL 3.0 HDM-DB)가 필요.
3. watermark의 무의미화: local free headroom은 host-local 개념 — pool 차원 압박 조율은 미정의.

$\rightarrow$ TPP의 kernel 메커니즘을 pool-aware coherent placement로 승격하는 것이 [[SkyByte]] 대비 내 차별점. (→ [[CXL Multi-node Coherence]], [[CXL Overview]])
