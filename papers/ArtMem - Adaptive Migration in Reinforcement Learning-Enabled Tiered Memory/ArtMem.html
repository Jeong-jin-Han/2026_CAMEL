Main topic Killer Application
ArtMem이 푸는 문제는 tiered memory(계층형 메모리)에서 어떤 page를 언제 fast tier(DRAM)로 옮길지 결정하는 migration policy(마이그레이션 정책) 그 자체다. 기존 시스템(AutoNUMA, MEMTIS, TPP 등)은 손으로 튜닝한 정적 hotness threshold(고정 임계값)나 휴리스틱에 의존하는데, ArtMem은 이를 경량 Q-learning 기반 강화학습(reinforcement learning, RL) agent로 대체해 workload가 바뀌어도 사람 개입 없이 실시간으로 migration scope(옮길 page 수 + hotness threshold)를 조정한다.

Killer application 1 — 휴리스틱 없는 online adaptive migration: fast-tier access ratio($\tau$) 하나만 관측해 migration 정책을 실시간으로 재학습하므로, workload별로 매번 새로 threshold를 튜닝할 필요가 없다.

Killer application 2 — 커널 안에서 실용적으로 도는 초경량 RL: state/action을 system-level $12$개 상태 $\times$ $9$개 action으로 극단적으로 압축해 두 Q-table을 합쳐 10KB 미만으로 유지하고, sampling overhead 3% CPU 이하, Q-table 연산 0.07% CPU 이하로 Linux kernel v5.15.19에 실제로 박아 넣어 오픈소스로 공개했다(github.com/Yitrus/ArtMem).

결과적으로 8개 workload, 7개 SOTA baseline 대비 평균 114% 성능 향상(범위 35%~172%)을 새로운 하드웨어 없이 정책 개선만으로 달성한다.
Original Abstract, p.1
This paper proposes ArtMem, a reinforcement learning (RL)-driven framework that dynamically manages tiered memory systems and adapts to workload evolution to address these limitations.
Main topic 필요한 이유 (Why It's Needed)
메모리 집약적 애플리케이션(그래프 처리, ML, in-memory DB)이 늘면서 DRAM만으로는 비용·용량 한계에 부딪힌다 — 여러 기업 데이터에 따르면 memory가 서버 비용의 약 40%를 차지한다. Byte-addressable PM(persistent memory)과 CXL(Compute Express Link)-enabled tiered memory가 비용 효율적 대안으로 떠올랐지만, 느린 tier의 지연시간(latency)은 DRAM 대비 최대 $2\times$에 달해 migration 정책의 정확도가 곧 성능을 좌우한다.

그런데 AutoNUMA, AutoTiering, Nimble, HeMem, Thermostat, Kleio, MEMTIS, TPP, Multi-Clock 같은 기존 시스템은 세 가지 근본 한계를 갖는다: (1) workload 의존성 — 정적 threshold/휴리스틱이 특정 workload에서만 잘 동작, (2) access ratio 미활용 — fast tier access ratio가 낮아졌을 때(=migration이 비효과적일 때) 정책을 조정하지 못함, (3) migration scope 고정 — 이동 page 수를 workload 패턴에 맞춰 동적으로 조정하지 못해 불필요한 migration 또는 fast tier 과소활용이 발생.

저자들은 MASIM 시뮬레이터로 4개 합성 access pattern(S1-S4, 총 32GB, DRAM 16GB)을 만들어 7개 기존 시스템의 실패 양상을 분석하고 세 관찰(Observation)을 도출했다: 기존 방법은 workload마다 성능 편차가 크고(Obs.1), fast tier access ratio가 성능과 강한 상관관계(Pearson $0.81$~$0.89$)를 가지며(Obs.2), migration scope는 workload마다 동적으로 튜닝돼야 한다(Obs.3, 수동 튜닝으로 Liblinear/XSBench에서 각각 47%/42% 향상 확인).
Original Abstract, p.1
This paper identifies three key limitations in existing tiered memory solutions. First, existing solutions often perform differently across different workloads, leading to suboptimal performance in some workloads. Second, they often fail to adjust migration strategies in response to low fast memory tier access rates, resulting in ineffective data placement. Third, they often miss the opportunity to dynamically tune the memory migration scope based on workload patterns, leading to unnecessary page migrations and under-utilization of tiered memory potential.
Main topic 해결책 (Solution)
ArtMem은 Q-learning 기반 model-free RL을 system-level(page 단위가 아닌) state/action으로 설계해 Q-table 폭발을 피한다. 아키텍처는 3계층(RL Framework - ArtMem 함수 계층 - Hardware)으로 구성된다(Fig.5, 우측 노드 참고).

State: fast memory access ratio $\tau$를 $k+1$개 구간으로 discretize.

$$\tau = \left\lfloor \frac{DRAM_{access} \times k}{DRAM_{access} + PM_{access}} \right\rfloor$$

Action: migration scope = migration number(이동 page 수) + hotness threshold(hot/cold 판정 기준), 각각 독립 Q-table 2개로 협력 조정.

Reward: 목표 access ratio 대비 편차와 직전 대비 개선분을 함께 고려.

$$r = \tau_i - \beta + \lambda(\tau_i - \tau_{i-1})$$

migration scope 결정에는 두 축이 더해진다 — EMA(exponential moving average)로 access frequency를 base-2 exponential bin으로 경량 추적하고 200만 sample마다 cooling하며, LRU 기반 page sorting으로 recency를 반영해 migration 후보를 고른다. 구현은 Linux kernel v5.15.19 프로토타입(오픈소스, github.com/Yitrus/ArtMem)으로, 2MB huge page를 migration 단위로 쓰고 코어당 sampling thread(ksampled)와 시스템 단위 migration thread(kmigrated)를 두어 RL 연산을 application critical path에서 분리한다.
Original §4.2, p.5
ArtMem employs a Q-learning–based, model-free reinforcement learning (RL) approach with constrained state and action spaces to minimize computational overhead.

Main topic 결론 (Conclusion)
ArtMem은 RL 기반 적응형 tiered memory 관리 프레임워크로, 실시간 fast memory 사용량에 맞춰 동적으로 조정함으로써 fast memory 활용도를 높이고 불필요한 migration을 줄인다. 평가 결과 SOTA 시스템 대비 평균 114% 성능 향상을 최소한의 overhead로 달성한다.

프레임워크의 일반성: reward를 latency 기반으로 바꿔도 access-ratio reward 대비 평균 3.4%만 낮고, Q-learning을 SARSA로 바꿔도 성능이 유사해 RL 알고리즘·reward 선택에 강건하다. Robustness 실험($5\times5=25$개 workload 조합)에서는 7개 조합만 10% 초과 성능 저하를 보였고, 잘못된 Q-table로 시작해도 평균 3 iteration(1~6) 만에 목표 성능의 95%에 도달한다.

한계: (1) per-page가 아닌 system-level 결정이라 세밀한 hot/cold 구분은 page sorting에 의존한다. (2) Liblinear처럼 초기 access가 균일한 workload에서는 access ratio가 0%까지 급락 후 회복하는 데 시간이 걸린다(ramp-up 속도가 sampling 정확도에 좌우됨). (3) 평가는 Optane PM 기반 단일 소켓 시스템으로, 실제 CXL 하드웨어 실측은 없다(latency emulation으로 CXL 가능성만 논의). 논문은 3-tier 이상 확장이나 multi-host 공유 시나리오는 다루지 않는다.
Original §7, p.13
This paper introduces ArtMem, a tiered memory system leveraging reinforcement learning for adaptive memory management. By dynamically adjusting based on real-time fast memory usage, ArtMem optimizes fast memory utilization while reducing unnecessary migrations. The evaluation shows ArtMem outperforms state-of-the-art systems, achieving an average performance improvement of 114% with minimal overhead.

Figure 5 illustrates the overall architecture of the proposed system, which is composed of three main components. At the top layer lies ArtMem's reinforcement learning (RL) framework, responsible for training and decision-making.
Method State: fast memory access ratio τ (Eq.1)
State는 $DRAM_{access}$와 $PM_{access}$ 샘플 수로부터 계산한 fast tier access ratio를 $k+1$개 구간으로 discretize한 값이다.

$$\tau = \left\lfloor \frac{DRAM_{access} \times k}{DRAM_{access} + PM_{access}} \right\rfloor$$

$\tau = k$는 모든 샘플이 DRAM에서 발생했음을 뜻한다. $DRAM_{access} = PM_{access} = 0$(샘플이 아예 없는 경우, 예: CPU 캐시 히트로 메모리 이벤트 자체가 안 잡힌 경우)은 access ratio 0과 의미가 다르므로 별도 state($k+1$)를 부여해, $k=10$일 때 총 12개 state를 쓴다.
Original §4.2, p.5
where τ = k means all sampled accesses happen in the DRAM with PM_access = 0. It is important to note that a state value of 0 might indicate all accesses occur in the slow memory tier or no events were sampled (DRAM_access = PM_access = 0, e.g., most of the accesses hit in the CPU cache or the event of concern did not occur), we set a separate state (k + 1) for the latter.
Method Action: migration number + hotness threshold (독립 Q-table 2개)
Action은 migration scope를 구성하는 두 파라미터 — 옮길 page 수(migration number)와 hot/cold 판정 기준(hotness threshold) — 로 정의되며, 각각 별도 Q-table과 독립 action set을 갖고 협력적으로 조정된다. 구현에서는 threshold action이 $\pm8$/$\pm4$/$0$(최소 16 accesses 유지), migration size가 16MB부터 2배씩 최대 2048MB + 0MB(no migration) 옵션까지 총 9개다. per-page가 아닌 system-level scope로 정의해 Q-table 크기를 억제한다.
Original §4.2, p.5
Based on observation 3, ArtMem adopts migration scope as the action, which depends on two key parameters: the migration number and the hotness threshold. Two separate Q-tables and independent action sets are designed to adjust these parameters dynamically and collaboratively.
Method Reward: τᵢ − β + λ(τᵢ − τᵢ₋₁) (Eq.2)
Reward는 세 항으로 구성된다.

$$r = \tau_i - \beta + \lambda(\tau_i - \tau_{i-1})$$

$\tau_i$(현재 access ratio, 높을수록 좋음), $-\beta$(목표 access ratio 대비 편차 penalty — 이게 없으면 agent가 access ratio를 인위적으로 진동시켜 reward를 착취해 시스템을 불안정하게 만들 수 있음), $\lambda(\tau_i-\tau_{i-1})$(직전 대비 개선/악화에 대한 보상이되, 직전 period에 migration이 없었으면 $\lambda=0$으로 꺼서 workload 자체의 변화에 잘못 책임을 묻지 않음).
Original §4.2, p.5-6
If the reward were defined solely as the increase in the fast memory tier access ratio between consecutive phases (i.e., τ_i − τ_{i−1}), the agent might exploit this by inducing large access ratio fluctuations to gain more rewards, potentially destabilizing system performance.
Method EMA: base-2 exponential bin + 2백만 sample cooling
memory access frequency는 흔히 Zipfian/Pareto 분포를 따른다는 전제 하에, ArtMem은 각 page의 access count를 base-2 exponential bin에 그룹화해 access 분포를 경량으로 추적한다. sampling마다 해당 page의 bin을 갱신하고, 2백만 sample마다 모든 bin count와 per-page access record를 절반으로 감쇠(cooling)시켜 오래된 정보를 할인한다. hot page threshold는 초기엔 DRAM 용량 기준으로 설정되고 cooling마다 reset된 뒤, cooling 사이 구간에서는 RL이 학습한 정책으로 refine된다.
Original §4.3, p.6
ArtMem records the number of memory accesses each page receives, grouping them into exponential bins with base 2 to compactly represent the access distribution. Upon each access sampling, the corresponding page is checked for bin reassignment, and the bin counters are updated accordingly. Additionally, a cooling operation is triggered every two million samples, during which all bin counts and per-page access records are halved to gradually discount stale information.
Method Page Sorting: aggressive active-list 재삽입
recency 정보는 LRU 기반 page sorting으로 반영한다. fast tier와 capacity tier 모두 active/inactive list를 유지하며, demotion 후보는 fast tier의 inactive list tail에서, promotion 후보는 capacity tier의 active list head에서 우선 고른다. 기존 설계(MEMTIS, AutoNUMA 등)는 migration된 page가 원래 tier에서의 activity status를 그대로 유지하는 보수적 정책을 쓰는데, 이는 premature demotion으로 인한 성능 jitter를 유발한다. ArtMem은 대신 migration된 page를 무조건 fast tier active list의 head에 삽입하는 aggressive 정책을 써서 최근 접근된 page를 즉시 우선시한다.
Original §4.3, p.6
Existing inter-layer page migration strategies [30, 58] adopt a conservative strategy: when a page is migrated, it retains its activity status from the source memory tier. This approach can cause premature demotion, leading to performance jitter.
Method Kernel 구현: 2MB huge page + ksampled/kmigrated + heuristic min threshold=16
page migration 단위는 2MB huge page로, 주소 변환 오버헤드를 줄이고 compound_page의 미사용 struct page를 재사용해 access data를 추가 메모리 소모 없이 저장한다. 코어당 sampling thread(ksampled)가 PEBS로 memory load event를 수집해 ring buffer에 쌓고, 시스템 단위 migration thread(kmigrated)가 이를 소비해 실제 migration을 수행한다. memory cgroup 아래 mount point(memory.hit_ratio_show, memory.action_show, memory.threshold_show)로 user-space RL agent와 통신한다.

RL exploration 중 threshold가 지나치게 낮아져 thrashing이 나는 것을 막기 위해 최소 hotness threshold(16 accesses)를 heuristic으로 고정한다. Q-table은 $12$ state $\times$ $9$ migration size(threshold $\pm8$/$\pm4$/$0$ 포함)로, 두 Q-table 합계가 10KB 미만이다.

Question 3+ tier(CXL Type-3 포함)로 확장 시 state/action space는?
ArtMem은 2-tier(DRAM+PM)를 전제로 state를 access ratio 하나, action을 migration number+threshold 두 Q-table로 압축했다. tier가 3개 이상(예: DRAM - CXL Type-3 - PM/NVM)으로 늘면 pairwise access ratio를 어떻게 하나의 state로 합칠지, migration 방향(어느 tier에서 어느 tier로)까지 action에 포함시켜야 하는지가 자명하지 않다. 논문은 이 확장을 미해결로 남긴다.

Gap / Idea 단일 소켓·단일 노드 실험 — multi-node CXL 공유는 다루지 않음
평가는 Intel Xeon 1개 소켓 안에서 DRAM을 fast tier로, Optane PM을 ndctl로 구성한 'remote memory node'를 slow tier로 써서 진행됐다(§6.1). CXL은 Introduction에서 PM과 같은 급의 latency를 갖는 slow tier 후보로만 언급될 뿐, CXL fabric을 통한 여러 host/socket 간 memory pool 공유나 multi-node coherence는 논문 어디에서도 다뤄지지 않는다. RL state(fast tier access ratio $\tau$)와 Q-table도 단일 cgroup·단일 노드 기준으로 정의돼 있어, 여러 노드가 같은 CXL-attached capacity tier를 공유하는 상황에서 이 state 정의가 그대로 성립하는지는 논문이 침묵하는 지점이다.

Memo Feasibility-by-building 관점: kernel-level RL을 10KB Q-table로
이 논문이 흥미로운 지점은 RL을 이론적으로만 제안하지 않고 실제 Linux kernel v5.15.19에 background thread(ksampled/kmigrated)와 cgroup 인터페이스로 박아 넣어 오픈소스로 공개했다는 것이다(github.com/Yitrus/ArtMem). state/action space를 극도로 압축($12$ state $\times$ $9$ action)해서 Q-table을 10KB 미만으로 만들고, 이를 통해 'RL이 커널 안에서 실용적으로 돌아간다'는 것을 실측 overhead(sampling $\leq3\%$, Q-table 연산 $\leq0.07\%$)로 증명한다. correct-by-construction까지는 아니지만, feasibility-by-building 스타일로 큰 아이디어를 최소한의 실제 구현으로 검증한 사례라 참고할 만하다.
Memo 내 연구방향과의 연결: multi-node CXL coherence 관점에서 본 ArtMem
내가 보는 CXL multi-node coherence 문제는 '여러 host가 같은 CXL-attached memory pool을 공유할 때 coherence/migration을 어떻게 조정할 것인가'인데, ArtMem은 이 축을 아예 전제하지 않은 single-node NUMA-style 설계다. RL state가 ($DRAM_{access}$, $PM_{access}$) 두 카운터만으로 정의되는데, 만약 여러 노드가 하나의 CXL capacity tier를 나눠 쓴다면 (a) 노드별 access ratio를 어떻게 집계할지, (b) 한 노드의 migration decision이 다른 노드가 보는 access ratio(따라서 reward)에 간섭을 일으킬지, (c) Q-table을 노드별로 독립시킬지 공유할지가 새로 풀어야 할 문제로 남는다. 즉 ArtMem의 '기법'(EMA+page sorting+RL)은 재사용 가능하지만 '문제 정의'(single-node state/reward) 자체를 multi-node coherence 상황에 맞게 다시 세워야 한다 — 이게 내 연구가 채워야 할 gap과 정확히 맞닿아 있다.
Memo Tabular이기 때문에 workload별 policy library가 거의 공짜
ArtMem이 tabular Q-learning을 쓴다는 설계 선택 하나가, 이후의 확장 가능성까지 결정한다. Q-table 두 개를 합쳐도 10KB 미만이라, workload별로 별도 Q-table을 저장해뒀다가 필요할 때 스왑하는 게 사실상 공짜다 — 교체 비용은 10KB memcpy 수준으로 $\sim\!1\mu s$, 반면 처음부터 재학습하려면 여러 migration과 reward 관측이 필요해 밀리초(ms) 단위가 걸린다. 이 부등식이 압도적으로 성립하기 때문에 '교체 속도'는 최적화 대상이 아니다.

만약 ArtMem이 DQN(신경망 기반)이었다면 이 아이디어는 훨씬 비쌌을 것이다 — workload마다 신경망 가중치를 통째로 저장하거나, catastrophic forgetting을 막기 위해 EWC·progressive network 같은 무거운 기법이 필요했을 것이다. tabular라는 설계 선택이 '정책 library' 확장 아이디어의 실현성 자체를 결정한다.
Gap / Idea 진짜 병목은 저장·교체가 아니라 phase detection
persist는 싸다(tabular, 10KB 미만). swap도 싸다(memcpy, $\sim\!1\mu s$). 학습조차 state/action을 제약하면 싸다(밀리초 단위). 이 셋을 다 확인하고 나면 남는 병목은 딱 하나 — 지금 도는 워크로드가 무엇인지, 언제 바뀌는지를 아는 것(phase detection)이다.

memory-tiering 레이어에는 애플리케이션 라벨이 올라오지 않으므로, 결국 access pattern만으로 phase를 판별해야 한다. 이건 완전히 새로운 문제가 아니라 컴퓨터 아키텍처의 오래된 계열 — SimPoint(BBV clustering), DAMON, MTM, Memtis(SOSP'23)류의 phase detection/tracking 연구와 정확히 맞닿아 있다. ArtMem 자체는 이 detection 문제를 다루지 않고, access ratio 하나로 뭉뚱그려 '지금 상태'만 본다 — '다음에 뭐가 올지'는 전혀 예측하지 않는다.
Gap / Idea 핵심 evaluation gap: ArtMem의 dynamic은 concurrency이지 recurrence가 아니다
ArtMem이 'dynamic and complex access pattern'이라 부르며 테스트한 실험은 실제로는 서로 다른 도메인의 워크로드 여러 개를 동시에(concurrent) 돌린 것이다 — 시간에 따라 워크로드가 바뀌었다가 되돌아오는 A, B, A, B 같은 순차적 recurrence는 어디에도 없다.

세 regime을 구분할 필요가 있다: Mixed(공간적, concurrent) — ArtMem이 실제로 테스트한 것. Switching(시간적, sequential) — 워크로드가 시간에 따라 바뀜. Recurring(A,B,A,B) — 이전 워크로드가 되돌아옴, 저장된 policy를 재사용하는 것이 이득을 보는 유일한 지점.

concurrent mixing은 결국 하나의 (준)정상적인 blend 분포로 수렴하므로, 단일 지속 적응 agent가 그 blend에 수렴하고 나면 끝이다 — recurrence 축을 전혀 자극하지 않는다. ArtMem 초록은 'workload evolution(시간적 변화)에 적응한다'고 주장하지만, 실제 증거는 concurrency(공간적 혼합)다. 주장은 시간, 증거는 공간 — 이 간극이 ArtMem 실험 설계의 evaluation gap이다.
Memo 오픈소스 하네스로 확증: 순차 phase-switching 장치가 코드에 없다
ArtMem은 소스 전체를 공개했다(github.com/Yitrus/ArtMem). setup 문서의 `artm_ctrl_start` 하네스를 보면 두 모드뿐이다: (1) 벤치마크 스크립트 하나를 인자로 받아 그 프로세스 하나만 시작부터 끝까지 모니터링, (2) `-` 인자로 system-wide 모니터링. A가 수렴할 때까지 돌고, B로 전환하고, 다시 A로 복귀하는 세션 내 순차 recurrence를 만드는 장치는 둘 중 어디에도 없다.

커널 파라미터(`artmem_adaptation_period`, `artmem_cooling_period`, `artmem_thres_cooling_alloc`, `artmem_promotion_period_in_ms` 등)도 전부 전역 RW 노브로 한 번 수동 세팅되는 값이지, workload별 학습값이 아니다 — 'adaptive'라는 이름이 무색하게 그 적응 범위가 수동으로 고정된 scaffold 위에서만 움직인다.

정확한 문장으로 정리하면: ArtMem의 'dynamic'은 concurrency이지 sequential recurrence가 아니며, recurrence는 이 논문의 실험에서 격리되지 않았다. (단, 하네스가 recurrence 스크립트를 금지하는 것은 아니다 — 단지 논문도 setup 문서도 제공·사용하지 않았을 뿐이다.)

Question Discriminating experiment: concurrency vs recurrence를 분리하려면?
ArtMem 자체의 오픈소스 하네스(`artm_start(-1)`, system-wide 모드) 위에 $A \rightarrow B \rightarrow A \rightarrow B$ 순차 시퀀싱 드라이버를 얹으면, '상대 코드를 그대로 testbed로 썼다'는 반박을 원천 차단하면서 이 gap을 직접 검증할 수 있다.

측정 대상: A로 복귀할 때마다 단일 적응 agent가 다시 수렴하는 데 드는 비용(A 실행시간 대비 %). baseline 비교는 '저장된 A-policy를 재로드'(제안) vs '매번 재학습'(ArtMem 기본). 이득이 커지는 조건은 A와 B의 optimal policy가 서로 충돌할수록.

남은 질문: phase 판별이 부정확할 때(엉뚱한 policy를 로드했을 때) 비용이 misprefetch보다 훨씬 크다는 점을 어떻게 견딜 것인가 — confidence threshold·hysteresis·최소 dwell time 같은 안전장치가 필요해 보이는데, 이게 이 아이디어의 novelty를 얼마나 깎아먹는지가 다음 확인 포인트다.
