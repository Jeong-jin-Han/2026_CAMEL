# Offline vs. Online prefetching
HW prefetcher는 복잡성 제약에 직면
5Ghz clock 주파수로 작동하는 최신 CPU 코어에서 prefetching 결정을 위한 시간 옛나은 종종 나노초 미만 수준이다

이러한 지연 시간 요구 사항은 엄격한 코어 영역 및 전력 제약 조건과 함께 online prefetching을 저렴한 로직을 사용하는 
간단한 알고리즘으로 제한한다

결과적으로 이러한 알고리즘은 더 긴 프로그램 컨텍스트를 분석하거나 더 많은 정보를 바탕으로 결정을 내릴 여유가 없다.

Offline prefetchers는 더 큰 컴퓨팅 예산을 활용하여 보다 정확한 prefetch 결정을 내리는 방법으로 연구되고 있다.
이러한 예산을 활용하는 두 가지 주요 방법
    1. 컴파일러 기반 접근 방식
    2. 프로파일 기반 접근 방식


# 컴파일러 기반 접근 방식 과 문제점
컴파일러 기반 접근 방식[9]은 컴파일 시간에 프리패치 명령어를 배치할 위치를 결정하기 위해 수동으로 설계된 휴리스틱에 의존한다.
이 접근 방식은 기준선 대비 개선을 보여주지만, 그 효과는 휴리스틱을 설꼐하는 설계하는 인간 전문가에 달려 있다.

일반적으로 이러한 휴리스틱은 특정 코드 패턴에 의해 트리거되므로 프로그램 수준에서 prefetching 결정에 대해 추론할 수 있는 능력이 부족하고 
더 복잡한 코드 구조에 적응할 수 없다.


# 프로파일 기반 접근 방식 과 문제점
프로파일 기반 최적화 접근 방식은 효과적인 정책을 찾을 때까지 prefetching 결정에 대한 가상 시나리오 정보를 수집하기 위해 프로그램을 한 번 이상 
컴파일하고 프로파일링합니다.
PGO는 광범위한 프로그램에서 뛰어난 성능을 보여주지만, 핵심적인 문제는 올바른 프로파일 정보를 수집하기 위해 프로그램의 입력 데이터가 필요하다는 점인데,
이는 항상 사용 가능한 것은 아닙니다.

프로그램의 입력이 알려지지 않았거나 크게 변하는 경우 PGO는 적용할 수 없다.


# 두 방식 모두에 해당하는 공통된 문제점

application이 비공개 소스이고 binary만 이용 가능한 경우, 두 offline 방식의 prefetching 분석을 적용할 수 없다
