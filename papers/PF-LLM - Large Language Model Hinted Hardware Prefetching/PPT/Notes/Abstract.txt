# 이 분야의 중요성에 대한 언급

# 기존에 어떤 것이 있었는지
정교한 HW prefetching 알고리즘이 존재  -> 정교하다는 것의 의미
# 기존의 한계점이 무엇이었는지
런타임 정보에만 전적으로 의존하는 것은 적응력과 더 넓은 프로그램의 문맥을 이해하는데 한계가 있다 -> 이것에 대한 자세한 문제 설명


# 저자의 핵심적인 통찰
load 명령에 최적의 prefetching 전략 코드 컨텍스트에서 파악할 수 있음

# 동기
숙련된 개발자들이 탁월한 능력을 발휘함 -> 이 근거는 어디에 있을까?
핵심 질문 제기
LLM을 이러한 분석을 자동으로 수행하도록 훈련이 가능한가?


# 도입한 것
PF-LLM: fine tuned된 LLM s.t load 명령어를 가지는 어셈블리 컨텍스트 -> LLM -> prefetching hint를 생성

생성된 prefetching hint (offline)는 LMHint Prefetcher에 소모됨
LMHint Prefetcher: 경량 HW prefetch ensemble

# 접근 방식
on chip HW prefetcher의 성능을 향상시킴
이유: 언제, 어떻게, 얼마나 적극적으로 프리페치를 수행하는가?
하드웨어적 결정 (런타임 하드웨어) -> offline LLM 기반 분석

on chip HW prrefetcher는 오라클 수준 시스템으로 전환
모든 load 명령어 항상 최적의 prefetching 정책을 따름

평가
메모리 집약적인 SPEC 2017 벤치마크 대비 -> 메모리 집약적인 것이 무엇인지 
2가지 베이스 라인 
SOTA HW prefetching 9.8%의 IPC

SOTA ensemble HW prefetching 18.9%의 IPC 

-> IPC가 무엇인지 

LLM을 활용한 마이크로아키텍쳐 결정을 내리는데 상당한 잠재력을 보여줌
-> 마이크로아키텍처가 무엇인지
